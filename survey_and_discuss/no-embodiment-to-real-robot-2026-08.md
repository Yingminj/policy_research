# 从「无本体」到真机：策略训练范式、相关研究与运动执行链路

**范围。** 「无本体训练」（robot-free / hardware-free policy learning）指**采集与训练阶段目标机器人不在场**的一整类做法——手持夹爪、可穿戴外骨骼、纯人类视频、仿真与生成式数据。本文回答四个问题：(1) 这类训练典型有哪些步骤；(2) 相关研究版图；(3) 从无本体到真机的运动执行链路上有哪些痛点与短板；(4) 怎么治。

## 0. 术语界定：三种「无本体」，别混为一谈

| 级别 | 定义 | 训练集里有真机轨迹吗 | 代表 |
|---|---|---|---|
| **L-A 完全无本体** | 采集端没有机器人，训练集里一条真机轨迹都没有 | 无 | Phantom [✓]、HumanEgo [✓]、EgoEngine [✓]、HiFi-UMI 的 zero-robot post-training [✓] |
| **L-B 无本体为主 + 真机锚点** | 大头是无本体数据，少量真机数据做对齐/后训练 | 少量 | UMI [✓]、EgoMimic [✓]、Masquerade（50 条/任务）[✓]、EgoHumanoid [✓] |
| **L-C 无真机采集，但本体模型在场** | 没有硬件，但有 URDF / 渲染 / 物理引擎 | 合成的"真机"轨迹 | sim-and-real co-training [✓]、DreamGen [✓]、SplatSim [~] |

还要与**跨本体（cross-embodiment）**区分：无本体 = 采集端没机器人；跨本体 = 训练端是 A 机器人、部署端是 B 机器人。两者共享**下游链路**的绝大部分问题（视觉 gap、动作空间 gap、动力学 gap），所以 Mirage [✓] 这类跨本体方法可以直接迁移到无本体场景使用——这是本文把它们并置的理由。

**一句话概括本文立场**：无本体训练的难点从来不在"策略学不学得会"，而在**从人类/虚拟的动作表示，一路转译到真机可执行的关节指令**这条链路上的每一次损失。

## 结论先行

1. **2026 年的状态：无本体数据已经能撑到"不要真机锚点"，但前提极苛刻。** HiFi-UMI 报告：仅用无本体 UMI 数据做 post-training，直接上真机部署，在三个 backbone 上与"在评估场景内采集的真机遥操作数据"相比成功率差 **−2.5 / +3.1 / −0.6 个百分点**，最强策略在精密插装任务上达 **85%** [✓]。但这个结论建立在**头戴离线双目惯性 SLAM、3 mm 工作空间局部末端精度、微秒级 GPIO 同步、每手两颗约 200° 广角相机**之上 [✓]。**结论不是"无本体够用了"，而是"无本体的上限由采集保真度决定，而不是由算法决定"。**

2. **决定成败的是链路，不是策略架构。** FeasibleCap 的数字最刺眼：无引导的手持采集，pick-and-place 任务的**不可行帧占比 83.1±16.9%**，加实时可行性引导后降到 **14.1±13.3%**；抛掷任务回放成功率从 **2/10 提升到 6/10** [✓]。也就是说，**在你训练之前，绝大多数帧对目标机器人根本不可执行**——这个损失发生在数据进入训练之前，任何策略改进都补不回来。

3. **痛点是三个 gap，不是一个。** 视觉 gap（人手/手持设备 vs 机器人外观、FOV、视角）、**动作/运动学 gap**（人手 7 自由度自由运动 vs 机械臂关节限位、奇异点、自碰撞、工作空间）、**动力学/控制 gap**（人手速度加速度超出机器人带宽、力与柔顺、接触、延迟）。文献对**前两个已有成熟解法**（inpainting/cross-painting；IK 过滤与重定向），**第三个是当前真正的瓶颈**——FeasibleCap 明确指出抛掷任务的残余失败集中在释放瞬间"一两帧内超出机器人速率限制的瞬态关节速度尖峰" [✓]。

4. **评估协议是公认的空白。** IJCAI 2026 综述把"设计能预测真实部署表现与迁移效率的评估协议"列为该领域三大开放挑战之一 [✓]。这与本仓库 `real-world-policy-evaluation-2026-08.md` 的结论完全一致：无本体训练**加剧**了这个问题，因为你连"在训练分布内"这个参照都没有了。

5. **最高性价比的三件事**（按投入产出排序）：**(a) 采集时的可行性闸门**（FeasibleCap 式的实时约束反馈，或 VISTA 式的离线打分过滤）；**(b) 仿真回放验证**（HiFi-UMI 对每条轨迹自动重建并做仿真回放验证 [✓]）；**(c) 部署侧的延迟与执行对齐**（UMI 的 latency matching [✓]、RTC [✓]）。这三件都不需要改策略，也不需要新硬件。

6. **对本仓库的直接含义。** 据 `real-world-policy-evaluation-2026-08.md` 记载（本次未重新审计）：部署侧下发的是**合成 Hermite 零速 S 曲线而非策略原始输出**，gripper 状态尺度约为训练范围的 **1.25 倍**。这两条正是本文 L7/L8 环节的教科书级失效模式。**在有真机数据时它们是误差，在无本体训练下它们是致命的**——因为无本体数据本来就没有经过真机执行的隐式校正，链路末端再叠一层未建模变换，训练分布与执行分布就彻底脱钩了。

## 1. 无本体策略训练的典型步骤

不管走哪条范式，流程都可以归约到同一条 9 段流水线。差别只在于**哪一段用什么技术填**，以及**哪一段被跳过**（跳过通常就是后面出问题的地方）。

### 1.1 统一流水线

```
S0 采集载体设计    →  S1 原始信号采集  →  S2 位姿/状态恢复  →  S3 结构化与切分
   (夹爪/外骨骼/眼镜/仿真)  (RGB/IMU/深度/编码器)  (SLAM、手部姿态、IDM)   (分段、语言标注、对齐)
                                                                       ↓
S8 评估与回流     ←  S7 真机部署      ←  S6 策略训练      ←  S5 观测对齐  ←  S4 动作转译与可行性过滤
   (成功率/失效归因)   (控制器/安全)      (BC/DP/VLA/共训)    (inpaint/渲染)   (重定向/IK/滤波)
```

### 1.2 逐段说明

**S0 采集载体设计.** 这一步是**用硬件设计预先消掉一部分 gap**，是最被低估的一步。
- 手持夹爪（UMI [✓]）：直接让人手持一个**与目标机器人同构的平行夹爪**，末端形态 gap 归零，只剩相机与臂的 gap。
- 可穿戴外骨骼（DexUMI [✓]、HumanoidExo [✓]、AirExo [~]）：DexUMI 用**可穿戴手部外骨骼**把人手运动约束到机器人手可行的运动学范围内，同时给采集者**真实触觉反馈**——即"硬件适配桥接运动学 gap，软件适配（机器人手 inpainting）桥接视觉 gap" [✓]。
- 眼镜/纯视频（EgoMimic 用 Project Aria [✓]、EgoDex 用 Apple Vision Pro [✓]）：零硬件约束、最大规模，但把全部 gap 推给下游算法。
- 仿真/世界模型：本体模型在场，gap 换成 sim2real。

**S1 原始信号采集.** RGB（常为鱼眼/广角）、IMU、可选深度或 LiDAR、夹爪开合（触发器编码器）。关键工程量在**多路时间同步**：HiFi-UMI 专门用一个**共享微秒级 GPIO 触发**来解决 [✓]。

**S2 位姿/状态恢复.** 无本体最脆弱的一段——**没有关节编码器，末端位姿只能靠估计**。
- 单目视觉 SLAM（UMI 原始方案）；
- 双目惯性 + 离线优化（HiFi-UMI，达到 3 mm 工作空间局部精度 [✓]）；
- LiDAR-centric SLAM（UMI-3D，针对"单目视觉 SLAM 在遮挡、动态场景、跟踪失败下脆弱"这一点 [✓]）；
- 纯视频路线：3D 手部姿态估计（Phantom、Masquerade 的第 (i) 步 [✓]）、4D 手物交互重建（EgoInfinity [✓]）。

**S3 结构化与切分.** 把非结构化视频切成"可训练的 episode"。IJCAI 2026 综述把这条单列为开放挑战之一 [✓]：in-the-wild 视频没有任务边界、没有语言标注、没有成败标签。

**S4 动作转译与可行性过滤.** 把人的运动变成**目标机器人能执行的动作**。
- 表示选择：UMI 用**相对末端位姿轨迹**，理由是对采集期跟踪误差和相机位移更鲁棒，并且与 SLAM 的增量式状态估计天然匹配 [✓]；
- 灵巧手需要**重定向（retargeting）**：向量式重定向（dex-retargeting / AnyTeleop 系）最小化人手与机器人手的关键点向量差，而非直接对齐关节角，以规避形态差异 [~]；
- **可行性过滤**：这是最常被跳过、代价最大的一步。UMI 原文即承认采集时下游机器人的运动学限制未知，需要靠数据过滤来保证可行性 [~]；FeasibleCap 把它前移到采集时做实时校验（可达性、关节速率限制、碰撞）[✓]；VISTA 把它做成离线三维打分（连续性 / 自碰撞 / 执行保真度）[✓p]。

**S5 观测对齐.** 让训练时的图像分布尽量接近部署时机器人相机看到的分布。
- **inpainting/overlay**：Phantom 与 Masquerade 抹掉人手臂、叠加渲染的机器人 [✓]；DexUMI 用高保真机器人手 inpainting [✓]；Mirage 的 cross-painting 在**执行时实时**把目标机器人抹掉、把源机器人画上去 [✓]。
- **生成式转译**：RwoR 在配对的"人手 / UMI 夹爪"数据集上训生成模型，把人手演示直接翻译成夹爪演示 [✓]。
- **视角补齐**：MV-UMI 指出手持夹爪只靠腕装第一视角相机会丢场景上下文，加第三视角后需要广域场景理解的子任务提升约 **47%**（3 个任务）[✓]。
- **感知先验对齐**：VISTA 指出腕装约 180° 鱼眼视角对预训练 VLM 属于 OOD，用 8M 规模 UMI-VQA 数据做适配 [✓p]。

**S6 策略训练.** Diffusion Policy / ACT / flow matching / VLA。无本体特有的两个选择：
- **共训比例**：EgoMimic 报告 2 小时机器人数据 + 1 小时手部数据强于 3 小时纯机器人数据 [✓]；sim-and-real co-training 报告仿真数据平均带来 **38%** 的真实任务提升，即使 sim 与 real 差异显著 [✓]；真实数据稀缺时最优混合比 α 可高达约 0.99 [~]。
- **无动作标签时的桥接表示**：IJCAI 2026 综述把它归为四类——**潜在动作表示、预测式世界模型、显式 2D 线索、显式 3D 重建** [✓]。代表：LAPA 用 VQ-VAE 目标学帧间离散潜在动作，再用少量真机数据把潜在动作映射到机器人动作 [✓]；DreamGen 用视频世界模型生成"神经轨迹"，再用潜在动作模型或逆动力学模型（IDM）反解伪动作 [✓]。

**S7 真机部署.** 见 §3 的 L6–L8，本文重点。

**S8 评估与回流.** 无本体路线的评估比常规更难：训练集里没有真机数据，**离线指标与真机成功率之间连"同分布"这个假设都不成立**。

### 1.3 五种范式在这条流水线上的差异

| 范式 | S0 载体 | S2 位姿来源 | S4 主要手段 | S5 主要手段 | 特点 |
|---|---|---|---|---|---|
| **手持夹爪（UMI 系）** | 同构夹爪 | 视觉/惯性/LiDAR SLAM | 相对末端轨迹 + 可行性过滤 | 腕视一致、少量视觉 gap | 末端 gap 最小、规模化最成熟 |
| **可穿戴外骨骼** | 手部/全身外骨骼 | 外骨骼编码器 + SLAM | 硬件即约束，几乎不需重定向 | 机器人手 inpainting | 运动学 gap 硬件消解、有触觉 |
| **纯人类视频** | 眼镜/任意视频 | 手部姿态 + 4D 重建 | 重定向 + IK + 可行性 | inpaint + 机器人渲染叠加 | 规模最大、gap 最大 |
| **仿真 / 生成式** | URDF / 世界模型 | 引擎真值 / IDM 反解 | 天生可行（引擎内） | 渲染真实感 / GS | 无采集成本、有 sim2real gap |
| **跨本体已有数据** | 别人的机器人 | 别人的编码器 | 动作空间归一化 | cross-painting | 无采集成本、动作语义不一致 |

## 3. 运动执行链路：从无本体到真机

这是本文的核心交付物。链路分 **L0–L8 九个环节**，每个环节给出：**这一环产出什么 → 无本体特有的痛点 → 真机上的失效表现 → 可观测指标 → 对策与文献**。

```
[无本体侧]                                    [真机侧]
L0 载体 ──▶ L1 位姿估计 ──▶ L2 动作表示 ──▶ L3 可行性 ──▶ L4 观测对齐 ──▶ L5 训练
                                                                              │
                              L8 评估回流 ◀── L7 控制器执行 ◀── L6 推理与时序 ◀┘
```

### L0 采集载体 → 本体的形态映射

- **产出**：一个"代理本体"（proxy embodiment）——手持夹爪 / 外骨骼 / 人手本身。
- **痛点**：代理本体与目标机器人的**形态差**。夹爪指长、指面材质、开合行程、TCP 定义、相机安装位姿——任何一项对不上，后面每一环都在放大这个偏差。人手直接采集时形态差最大（多关节、软指、自由腕）。
- **失效表现**：策略学到的抓取深度/角度在真机上系统性偏移；夹爪闭合到位但抓空；TCP 定义差 1–2 cm 导致插装类任务全灭。
- **可观测指标**：代理夹爪与真机夹爪的 TCP 标定残差；开合行程映射的端点误差；相机外参差。
- **对策**：**用硬件消 gap** 是最省事的一档——UMI 直接用同构平行夹爪 [✓]；DexUMI 用外骨骼把人手约束到机器人手可行范围 [✓]；EgoMimic 反过来做——**造一个把运动学 gap 最小化的低成本双臂** [✓]。凡是 L0 没消掉的 gap，L3/L4 要花十倍力气补。

### L1 位姿与状态估计 → 无编码器的原罪

- **产出**：末端 6D 位姿时间序列 + 夹爪开合 + 时间戳。
- **痛点**：**没有关节编码器**。位姿来自 SLAM 或手部姿态估计，因此存在：尺度漂移、遮挡丢跟踪、动态场景失效、多路信号时间不同步。这是无本体相对遥操作**唯一无法回避的结构性劣势**——遥操作的动作标签来自机器人自身编码器，是真值；无本体的动作标签是估计值。
- **失效表现**：轨迹整体缓慢漂移导致长程任务末段偏离；抓取瞬间因遮挡跳变；图像与动作错位半个到几个控制周期，训练出"提前动"或"滞后动"的策略。
- **可观测指标**：SLAM 回环误差 / 重投影残差；工作空间局部末端精度（HiFi-UMI 的 3 mm 是当前公开的高水位 [✓]）；多路时间戳偏差与抖动；夹爪开合信号与图像的互相关延迟。
- **对策**：
  - 提升传感：双目惯性 + 离线优化（HiFi-UMI [✓]）、腕装 LiDAR（UMI-3D，明确针对单目 SLAM 在遮挡/动态/跟踪失败下的脆弱性 [✓]）；
  - 硬件同步：共享微秒级 GPIO 触发（HiFi-UMI [✓]）；
  - **表示层容错**：UMI 用相对末端位姿轨迹，理由就是"对采集期跟踪误差与相机位移更鲁棒，且与 SLAM 的增量式估计天然匹配" [✓]——这是用表示设计对冲估计误差的经典范例；
  - 原生优于重建：HiFi-UMI 强调双夹爪相对位姿取**原生测量而非重建** [✓]。

### L2 动作表示 → 语义必须在两侧一致

- **产出**：策略要预测的那个量（绝对/相对末端位姿、关节角、潜在动作、2D/3D 线索）。
- **痛点**：**同一个数字在采集侧与部署侧含义不同**。典型三类：
  1. **参考系**：世界系 / 基座系 / 相机系 / 上一帧系。无本体侧没有机器人基座，天然只能用相机或上一帧作参考，部署时若换成基座系就错。
  2. **绝对 vs 相对**：绝对位姿要求采集与部署共享同一个原点，无本体做不到；相对表示是主流解。
  3. **量纲与尺度**：夹爪开合的行程映射、单位（米/毫米）、归一化统计量。Open X-Embodiment 的做法是先归一化再离散化，输出按本体反归一化解释 [~]；但也有工作主张**保留原始物理量纲**，理由是"1 弧度或 10 厘米本身带有物理含义，归一化会把它抹掉" [~]。
- **失效表现**：**尺度错配是最隐蔽的杀手**——策略输出看起来"形状对"但幅度系统性偏大或偏小；夹爪永远闭不紧或过闭合。本仓库记录的 gripper 状态尺度约为训练范围 **1.25 倍** 就是这一类 [据 `real-world-policy-evaluation-2026-08.md`，本次未重审计]。
- **可观测指标**：训练集动作分布 vs 部署时实际下发动作分布的逐维直方图对比（均值、std、分位数）；这个对比应该是部署前的**强制门禁**，成本几乎为零。
- **对策**：相对末端轨迹（UMI [✓]）；任务坐标系接口（UMI on Legs 明确以"任务坐标系下的末端轨迹"作为高低层接口 [✓]）；跨本体统一动作空间（EgoVLA 的人机统一动作空间 [~]）；潜在动作（LAPA [✓]，代价是引入任务无关动态 [~]）。

### L3 可行性过滤 → 最常被跳过、代价最大的一环

- **产出**：一个**目标机器人确实能执行**的轨迹集合（以及被丢弃/被修正的部分）。
- **痛点**：采集时机器人不在场，**采集者对目标机器人的运动学一无所知**——工作空间越界、关节速率超限、自碰撞、IK 不收敛、奇异点附近雅可比病态，这些在采集时全部不可见，**只有在回放阶段才暴露**。UMI 原文即承认下游机器人运动学限制在采集时未知，需靠数据过滤保证可行性 [~]。FeasibleCap 把这个问题的严重性量化了：无引导采集的 pick-and-place，**83.1±16.9% 的帧对目标机器人不可行** [✓]。
- **失效表现**：任务前半段正常、放置阶段失败（IK 约束违反）；动态任务在释放/加速瞬间失败——FeasibleCap 明确定位抛掷任务残余失败在释放瞬间的"一两帧内超出速率限制的瞬态关节速度尖峰"，而基线的不可行帧则聚集在轨迹起始的猛烈挥摆处，部分归因于 IK 不收敛而非纯速率违反 [✓]。
- **可观测指标**：**不可行帧占比**（按可达性 / 关节速率 / 碰撞分别统计）；**仿真回放成功率**；每条轨迹的最大关节速度/加速度相对限值的裕度；IK 求解残差与迭代失败率。
- **对策**（三档，可叠加）：
  1. **采集时闸门（最优）**：FeasibleCap 的逐帧校验 + 设备端视觉叠加 + 触觉提示，让采集者当场改正；且其仿真实验表明**施加可行性约束不牺牲跨本体迁移** [✓]——这一条很关键，它反驳了"过滤会让数据变得只适配一种机器人"的直觉担忧。
  2. **离线打分与过滤**：VISTA 的连续性 / 自碰撞 / 执行保真度三维打分 [✓p]；HiFi-UMI 对每条轨迹**自动重建并经仿真回放验证** [✓]。
  3. **推理时投影（治标但有效）**：UMI-on-Air 的 EADP 把低层本体控制器的反馈注入扩散采样过程，直接在生成阶段保证对该本体动力学可行 [✓]。这一档的好处是**同一份数据可服务多种本体**，可行性在部署时才注入。

> **判断**：L3 是无本体链路里投入产出比最高的一环。它不改策略、不加硬件、不需真机，却能把训练集的有效性提升数倍。**没有 L3 的无本体流水线，本质上是在训练一个"人类能做但机器人做不到"的策略。**

### L4 观测对齐 → 视觉 gap

- **产出**：与部署时机器人相机分布一致的图像。
- **痛点**：四个子 gap——(a) **外观**：画面里是人手/手持设备而非机器人；(b) **视角与安装**：GoPro 的位置与机器人腕相机的安装位姿不同；(c) **光学**：鱼眼畸变、FOV、曝光策略、卷帘快门；(d) **上下文缺失**：只有腕视没有全局视角。
- **失效表现**：策略在真机上"看不懂"自己的手；机器人手臂进入视野被当成新物体；FOV 变化让空间关系整体错位。VISTA 进一步指出腕装约 180° 鱼眼对**预训练 VLM 而言是 OOD**，这使得大 VLA 反而比小策略更吃亏 [✓p]。
- **可观测指标**：训练/部署图像的特征分布距离（本仓库既有的 DINO CLS 余弦相似度框架可直接复用）；相机内外参差异；FOV 与畸变参数差。
- **对策**：
  - **抹除 + 叠加**：Phantom / Masquerade 抹人臂、叠渲染机器人 [✓]；DexUMI 高保真机器人手 inpainting [✓]；
  - **执行时 cross-painting**：Mirage 在部署时实时把目标机器人换成源机器人 [✓]——注意这一档把开销放在推理侧，需要实时分割与渲染；
  - **生成式转译**：RwoR 训练"人手→夹爪"的图像翻译 [✓]；
  - **补视角**：MV-UMI 加第三视角，广域理解子任务 +47% [✓]；
  - **补先验**：VISTA 用大规模鱼眼 VQA 数据把 VLM 适配到该光学分布 [✓p]；
  - **主动感知一致性**：ActiveUMI 记录操作者头部主动运动，让策略学"视觉注意与操作的关联" [✓]——部署时机器人也得有对应的主动视角自由度，否则这条数据反而是负担。

### L5 训练 → 混合、配比与负迁移

- **产出**：策略权重。
- **痛点**：无本体数据与（少量）真机数据的**混合配比**、以及**负迁移**。共训不是把两份数据拼起来就完事：机理分析指出**结构化表示对齐**是共训的主要内在效应，且"表示对齐"与"域可辨识性"**两者都必需**——盲目对齐而不保留域信息会导致负迁移 [~]。
- **可观测指标**：分域 loss 曲线；不同配比下的真机成功率（这必须真机测，见 L8）；表示空间的域可分性。
- **对策与已知配比证据**：
  - EgoMimic：2h 机器人 + 1h 手部 > 3h 纯机器人 [✓]；
  - Masquerade：675K 帧编辑视频预训 + 每任务 50 条真机微调，超基线 5–6×，且**性能随编辑视频量对数增长** [✓]（对数增长意味着规模化收益递减，别指望无脑堆量）；
  - sim-and-real：仿真平均 +38% [✓]，真实数据稀缺时最优 α 可高达约 0.99 [~]；
  - HiFi-UMI：把配比问题**取消掉**——不缩小真机比例，而是提升无本体数据保真度，直到真机锚点可以完全去掉 [✓]。这是 2026 年最值得注意的路线转向。

### L6 推理与时序 → 延迟、频率、块间断裂

- **产出**：一串带时间戳的动作指令。
- **痛点**：三件事同时发生——(a) **推理延迟**（大 VLA 数十到数百毫秒），块生成完时机器人与环境已经走过了，执行的动作基于过期观测 [~]；(b) **频率不匹配**：训练数据频率、策略预测频率、控制器频率三者不同，跨本体数据集里控制频率本身就高度异质（3 Hz 到 50 Hz）[~]；(c) **块间断裂**：相邻动作块交界处不连续。
- **无本体特有的加重**：真机遥操作数据里，采集频率就是机器人控制频率，天然自洽；无本体数据的"频率"是相机帧率或 SLAM 输出率，与目标机器人控制频率**毫无关系**，需要显式重采样，而重采样会改变速度/加速度的隐含语义。
- **失效表现**：抖动、卡顿、超调；动态任务（抛、接、擦）系统性失败；块交界处的速度尖峰——注意这正是 L3 里 FeasibleCap 观察到的失败模式 [✓]，**L6 会重新制造 L3 已经过滤掉的问题**。
- **可观测指标**：端到端延迟分解（相机曝光→传输→推理→下发→执行）；块交界处的速度/加速度跳变幅度；实际控制频率的抖动。
- **对策**：
  - **延迟匹配**：UMI 的 inference-time latency matching——推断并补偿相机读出、推理、机器人硬件各段延迟，使下发动作在时间上对齐 [✓]。这是 UMI 论文里与"相对轨迹表示"并列的两大部署设计之一，**却是被复现者最常忽略的一个**；
  - **实时分块**：RTC——执行当前块的同时生成下一块，冻结必然执行的动作、inpaint 其余；免重训，适用任意 diffusion/flow VLA [✓]；
  - **异步推理族**：VLASH（用上一块把状态前滚到执行时刻）[~]、LAGO [~] 等。

### L7 动作解码与重定向 → 从末端位姿到关节指令

- **产出**：关节角/速度/力矩指令。
- **痛点**：策略输出的是末端位姿（或潜在动作），到关节指令之间**还有一整套未被训练覆盖的变换**：IK 求解（多解、跳解、奇异点）、灵巧手重定向、轨迹插值与平滑、限幅与钳位、坐标系变换。
- **这一环是本仓库已知问题的所在**：据 `real-world-policy-evaluation-2026-08.md` 记载，部署侧下发的是**合成 Hermite 零速 S 曲线而非策略原始输出**（本次未重新审计）。这意味着**离线评估的对象与真正被执行的对象不是同一个东西**。
- **失效表现**：策略输出正确但执行轨迹形状被改变（零速端点会抹掉块内的速度连续性，正是 L6 想保住的东西）；IK 跳解导致肘部突然翻转；重定向在指尖接触瞬间偏差最大。
- **可观测指标**：**下发指令 vs 策略原始输出**的逐点偏差（这个日志应该默认开启）；IK 解的连续性（相邻帧关节角跳变）；重定向的关键点向量残差。
- **对策**：
  - **把 L7 纳入离线评估**：任何离线指标都必须走**与部署完全相同的后处理链路**，否则测的不是被部署的那个策略；
  - **重定向用向量式而非关节角对齐**（dex-retargeting / AnyTeleop 系，最小化人手与机器人手关键点向量差以规避形态差异 [~]）；
  - **平滑与插值要在训练侧同构**：Diffusion Policy 的常规做法是 10 Hz 预测、线性插值到 125 Hz 执行 [~]——插值方式属于策略接口的一部分，采集侧与部署侧必须一致；
  - **可行性感知的生成**：UMI-on-Air 的 EADP 把控制器反馈注入采样，等于把 L7 的约束前移到 L6 [✓]。

### L8 控制器与真机执行 → 力、柔顺与安全

- **产出**：真实运动与接触力。
- **痛点**：无本体数据**几乎不含力信息**。人手采集时的接触力、阻抗、柔顺策略全部丢失，只留下位姿轨迹。位置控制器忠实跟踪一条"人手做得到但机器人做起来会硬撞"的轨迹，就是硬件损伤。此外还有：负载差异、基座柔性、齿轮间隙、执行器带宽。
- **失效表现**：接触瞬间力过大（插装、擦拭、按压类任务）；柔顺任务表现远低于自由空间任务；抓取力不足或压碎。
- **可观测指标**：关节力矩/外力估计峰值；接触阶段的位置跟踪误差（跟踪误差大 = 在硬顶）；保护性停机次数。
- **对策**：
  - **采集端带回触觉**：DexUMI 的外骨骼在采集时提供**直接触觉反馈**，采集者因而会自然地做出机器人可承受的接触行为 [✓]；ManipForce 用带齿条齿轮与线性导轨的夹爪实现精确稳定的力引导演示 [~]；
  - **控制侧留柔顺**：变阻抗控制 / 阻抗策略 [~]；无本体轨迹跑位置控制的场合，至少要有力限幅与接触检测；
  - **本体特定低层控制器**：UMI on Legs 用仿真训全身控制器承接末端轨迹 [✓]；UMI-on-Air 的 EADP 同理 [✓]。**通用的高层 + 本体特定的低层，是这条链路最稳的分工。**

### L9 评估与回流（跨越 L0–L8）

- **痛点**：无本体训练把评估问题推到极端——训练集里没有真机数据，**没有"分布内"参照**；IJCAI 2026 综述把"设计能预测真实部署表现与迁移效率的评估协议"列为三大开放挑战之一 [✓]。
- **对策**：
  - **仿真回放验证**（HiFi-UMI 对每条轨迹自动重建 + 仿真回放验证 [✓]）——这既是数据过滤，也是最便宜的评估；
  - **运行时失效预测**（FIPER：RND 检 OOD + 动作块熵，用成功 rollout 做 conformal 校准，无需失效数据 [✓]）——在无本体场景下尤其有价值，因为你事先不知道策略在哪些状态上是幻觉；
  - **统计严谨性**：见 `real-world-policy-evaluation-2026-08.md`（真机试验次数与置信区间问题在此处同样适用，且更严重）。

## 5. 对策路线图

**立刻做（天级，不需硬件、不需重训）**
1. **动作分布门禁**：部署前自动对比训练集动作分布与实际下发指令分布，逐维输出均值/std/分位数差异，超阈值报警。治 P1。
2. **下发指令日志**：记录"策略原始输出 → 每一级后处理 → 最终下发"的完整链路，离线评估强制走同一条链路。治 P2。
3. **延迟审计**：测量相机曝光→传输→推理→下发→执行的分段延迟，实现 UMI 式延迟匹配。治 P5 一半。

**短期（周级）**
4. **离线可行性打分**：对每条无本体轨迹跑可达性 / 关节速率 / 自碰撞检查，输出不可行帧占比；先只做统计不做过滤，看清楚基线在哪。治 P0 的诊断部分。
5. **仿真回放验证**：把打分升级成"仿真里放一遍"，回放失败的轨迹标记或剔除。治 P0。
6. **RTC 或等价的异步执行**：免重训接入。治 P5 另一半。

**中期（月级）**
7. **采集时可行性反馈**：FeasibleCap 式的设备端视觉叠加 + 触觉提示。治 P0 的源头。
8. **观测对齐流水线**：视场景选 inpaint+overlay（离线、便宜）或 cross-painting（在线、实时开销）。治 P4。
9. **运行时失效预测**：FIPER 式 OOD + 动作块熵监控，先当作评估工具用。治 P8。

**长期（季度级）**
10. **采集保真度升级**：双目惯性/LiDAR SLAM、硬件级时间同步、广角多目。治 P3，并把 P0/P4 的天花板一起抬高——HiFi-UMI 的经验是**这条路能一路通到"不要真机锚点"** [✓]。
11. **本体特定低层控制器**：通用高层策略 + 仿真训练的本体控制器，接口定在任务坐标系末端轨迹上（UMI on Legs / EADP 范式）。治 P6、P0 的执行侧残余。

## 6. 对本项目的落地建议

结合 `real-world-policy-evaluation-2026-08.md` 记录的三仓库现状（本次未重新审计，请以该文为准）：

- **`robot_data_platform`（数据侧）**：数据审计文化已经很强（`conversion_manifest.json`、`audit.hold`、`unique_ratio` 等），**把 L3 的可行性检查加进同一套审计里是最自然的扩展**——多一列"不可行帧占比"，与现有的 `unique_ratio` 并列。这是全文性价比最高的一条建议。
- **`lerobot_vlahost`（策略侧）**：已有 `envs/{libero,robocasa,robotwin,...}` 仿真封装与 `rtc` 推理后端，**L5 的仿真回放验证与 L6 的 RTC 都是"接线"而非"从零造"**。`rewards/topreward/` 可以顺带当作 L9 的评估裁判用。
- **`Apex_Deploy_new`（执行侧）**：P1/P2 两条都落在这里，且都是极低成本。**在做任何无本体数据的实验之前先修这两条**——否则无本体带来的收益会被链路末端的未建模变换吃掉，而你无法归因。
