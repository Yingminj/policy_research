## 1. 结论

1. **上机口径（`policy_deployed`）下，三个旋钮谁都没动。** MAE
   `depth1` **0.03849** < `width512` **0.03876** = `head_diff` **0.03876** < `base` **0.03897**，
   **极差 1.2 %**，而本轮实测的采样判读线是 **1.70 %**（§3.3）。**全部落在噪声里。**
   null 同批 anchor：`hold_state` 0.07266、`train_mean` 0.22729，四者都是 null 的 1.86×–1.89×。
   **这次参数调整在部署口径上没有产生任何可读的改变。**
2. **裸策略口径（`policy_raw`）上只有两个旋钮读得出来，而且都是"减法"方向。**
   `head_diff` **0.03357**（−3.0 %）、`depth1` **0.03376**（−2.5 %）都超过 1.70 % 判读线；
   `width512` **0.03461** 对 `base` **0.03462** 是 **−0.03 %**，**读不出来**。
   null 对照 `hold_state` 0.07266（四者 2.10×–2.16×）、`train_mean` 0.22729（6.56×–6.77×）。
   **换句话说：把 trunk 从 8 层砍到 1 层（−22.9 % 参数）没有变差，反而好 2.5 %。**
3. **`dim_model` 256→512 是本轮唯一一个纯亏的旋钮。** +21 063 680 参数（+65.3 %）、
   推理慢 **1.44×**（`tables.md` 表 10），换来 flat MAE **−0.03 %**（读不出来）；
   同时它是四者里**最会背训练集的**：seen MAE **0.01617**、seen→unseen **2.14×**
   （`base` 1.89×、`head_diff` 1.52×、`depth1` **1.46×**）。**加宽度买到的是记忆，不是泛化。**
   唯一一处它确实读得出来的收益在末端位置：部署后 **23.82 mm** vs `base` 24.63 mm
   （−3.3 %，判读线 0.98 %），见 §4.3——**但同一列上 flat MAE 是平的**，两者不矛盾（§6.3）。
4. **记忆倍数与泛化收益严格反向，四个点一个例外都没有。**
   seen→unseen：`width512` **2.14×** / `base` **1.89×** / `head_diff` **1.52×** / `depth1` **1.46×**；
   同一顺序下 held-out raw MAE 是 0.03461 / 0.03462 / 0.03357 / **0.03376**。
   **越会记训练集的那一版，held-out 上越差或持平；这条比值不依赖任何判读线**
   （同一权重的两侧之比，差距 46 %–114 %，远超任何噪声尺度）。
5. **桥仍然是这张表上唯一的大数。** `policy_raw → policy_deployed`：
   `width512` **+12.0 %**、`base` **+12.6 %**、`depth1` **+14.0 %**、`head_diff` **+15.5 %**；
   部署栈其余三级累积是 **−1.8 %~−0.3 %**（小幅改善），**全部代价都在 K=40 桥这一级**（§5.1）。
   **桥的代价（12–15.5 %）是四个旋钮之间全部差距（raw ≤3.0 %、deployed 1.2 %）的 4–12 倍。**

**一句话：** **这次调的三个参数，在上机口径上一个都没动（极差 1.2 % < 判读线 1.70 %）；
唯一可操作的结论是"可以砍"——1 层 trunk 少 23 % 参数、推理快 26 %、部署 MAE 还是四者最低；
而同一份数据第二次说明，工程力气该投在 K=40 桥（12–15.5 %）而不是这几个旋钮（≤3.0 %）。**

## 2. 评测集审计（在任何精度表之前）

### 2.1 这次到底改了什么：一次真正的单变量消融，但每个旋钮都拖着东西

`probes/config_diff.txt` §3 的逐字段比对：**三个权重相对 `base` 各只有 1 个字段不同**，
55 个共有字段里其余 54 个逐位相同。这是 09-05 那轮没有的条件——那轮 head、视觉骨干、
trunk 形状**同时动了三样**，而且分属两个策略类型（共有字段变了 7 个、新增 15 个、删掉 25 个）。

**但"改了一个字段"不等于"改了一件事"**（`probes/config_diff.txt` §4）：

| 权重 | head | sincos 频率基（`sincos_variant`） | 积分步数 | trunk | FFN 比 |
|---|---|---|---:|---|---:|
| `base` | flow | openpi（0.004–4.0） | 10 | 8 × d256 / ff1024 | 4.0× |
| `head_diff` | **diffusion** | **ddpm（base 10000）** | **100** | 8 × d256 / ff1024 | 4.0× |
| `depth1` | flow | openpi（0.004–4.0） | 10 | **1** × d256 / ff1024 | 4.0× |
| `width512` | flow | openpi（0.004–4.0） | 10 | 8 × **d512** / ff1024 | **2.0×** |

两条拖带项都不出现在字段 diff 里：

- **`action_head` 顺带翻了时间嵌入的频率基**：`time_sincos="auto"` 解析成
  `"ddpm" if action_head == "diffusion" else "openpi"`
  （`configuration_patch_new_policy.py:214-218`），并且把 10 步 Euler 换成 **100 步 DDPM**
  （`num_inference_steps=null` → 回落到 `num_train_timesteps=100`，`modeling_...py:450`）。
  **所以 `head_diff` 是"head + 时间基 + 积分步数"三合一，不是单机制改动。**
- **`dim_model` 256→512 不动 `dim_feedforward`**（仍是 1024），FFN 比例从 **4.0× 掉到 2.0×**。
  +21 M 参数几乎全在注意力和投影上，不在 MLP 上。**这不是等比放大。**

> **`current_loss` 只能三选三比，不能四个一起比。**
> `base` 0.016 / `depth1` 0.026 / `width512` 0.012 是同一个目标（flow 速度场 MSE），**可以横比**；
> `head_diff` 的 0.014 是 DDPM 的 epsilon-MSE，**不能和另外三个比**。
> 这是本轮相对 09-05 的一处改善——那轮三个权重三个不同目标，一个都不能比。
> 本报告不把任何 `current_loss` 用作结论依据。

### 2.2 来源与污染：0 个 episode 被丢

`probes/splits.txt`：这 53 个 EEF episode 与关节版评测集是**同一批录制**
（`observation.velocity` 指纹 53/53 命中，episode-index 是恒等置换）。
按 `action` 数组的 SHA1 逐 episode 比对七个数据集：

```
batch_success_53_eval_data_eef  in batch_success_361_eef  : velocity 0  action 0
batch_success_53_eval_data_eef  in batch_success_505_eef  : velocity 0  action 0   <- 四个权重的训练集
batch_success_53_eval_data_eef  in batch_success_533_eef  : velocity 0  action 0
```

16 次 held-out 评测全部传了 `--train-root batch_success_505_eef`，harness 每次都报
**505 个唯一训练 episode 指纹、丢弃 0 个**（`results/*.log`），
**四个权重的 anchor 集合因此逐个相同（2007 个 / 97 090 个有效动作步）**——
`summarise.py --selftest` 把这条写成断言（表 11）。

### 2.3 OOD 率：0.24 %，只有一个通道

`probes/ood.txt`：以 `batch_success_505_eef` 的 MIN_MAX 统计箱为界（四个权重的归一化器
就是用它建的，且四份**逐位相同**），40 132 帧里 **98 帧（0.24 %）** 至少有一个通道越界，
全部落在 `eef_r_x` 一个通道上，**最大越界 0.0301 raw 单位（= 30.1 mm）**。
其余 13 个通道越界 0 帧。**这个量级不解释本报告里的任何差异。**

### 2.4 对齐自检：四个 checkpoint 各一次，全过

`probes/check_alignment.txt`。这是唯一一个"错了还看着合理"的地方——
`action_delta_indices` 从 `1 - n_obs_steps` 起步，batch 里带着历史帧的动作。

| checkpoint | `n_obs_steps` | 动作窗口 | 计算出的 offset | 负对照 | 结论 |
|---|---:|---|---:|---|---|
| `base` / `head_diff` / `depth1` / `width512` | 2 | −1..49 | 1 | 各 8/8 触发 | 四份全 OK |

观测锚点 = 窗口**最新**一帧（部署的 Hermite 桥就是从这一帧的实测位姿起步的），
动作 offset = `n_obs_steps − 1`。**三个旋钮都没有改变这两条。**

### 3.3 判读线：本轮四次抽样，逐个 head 单独测

`--seed-repeat 3`（共四次抽样：seed 0 + 三次重抽）。
**四个 head 全都从 `torch.randn` 起步**（`modeling_patch_new_policy.py:540` flow / `544` diffusion），
所以四个都要抽——把任何一个当确定性 head 会让两次跑出不同的数而没人知道为什么。

| 指标 | `base`(flow) | `head_diff`(diffusion) | `depth1`(flow) | `width512`(flow) | 本报告采用 |
|---|---:|---:|---:|---:|---|
| mae 极差 | **1.70 %** | 1.07 % | 1.38 % | 0.80 % | **1.70 %** |
| acc@0.25σ | 0.53 % | 0.48 % | 0.37 % | 0.23 % | **0.53 %** |
| 末端位置均值 | 0.87 % | 0.98 % | 0.82 % | 0.94 % | **0.98 %** |
| 末端 acc@5 mm（左臂） | 26.76 % | **28.96 %** | 9.03 % | 3.11 % | **29.0 %** |
| 末端 acc@10 mm（左臂） | **11.73 %** | 6.78 % | 5.30 % | 1.23 % | **11.7 %** |

取每个指标上**最差那一臂**的极差作判读线（不是平均，也不是主角自己那一条）。

> **`--seed-repeat 1` 会给出一条恒为 0 的判读线。** 1 次重抽只有两个点，极差是两点距离；
> 09-05 报告 §3.3 已经实测过 2 次抽样把末端容差列的线估紧约 4 倍，1 次抽样连极差都构造不出来。

> 5 mm 上 3.11 % vs 28.96 %）。用一条错的线读这张表会直接读反。

## 5. 部署窗口：重写掉了多少，掉在哪一级、哪几步

部署配置 `deploy_config_eef.yaml` 是 `strategy: base` + `inference.type: chunk`，
`BaseStrategy.run`（`strategies/base.py:69`）因此走 `send_next_action_chunk`，

## 6. 机制：为什么是这些数

### 6.1 head 那一路：09-05 报告 §7.2 的解释在受控条件下不成立

09-05 报告 §7.2 说：`pp_new`（flow）相对 `pp_old`（diffusion）是"**前段更准、尾部更散**"，
并把它归给 flow matching"少步数、无纠错"——
*"flow matching 的回归目标是一条常速路径的速度场，一次前向就定方向，10 步 Euler 积分不做
去噪意义上的纠错；DDPM 的 100 步每步都往数据流形上拉一次"*。

本轮把 head 单独换掉、其余 54 个字段逐位不动，**结论相反**：

| | @1 | tail ratio | rmse | @50 |
|---|---:|---:|---:|---:|
| `base`（flow，10 步 Euler） | 0.01658 | 1.73 | 0.07610 | 0.03462 |
| `head_diff`（diffusion，100 步 DDPM） | **0.01618** | **1.70** | **0.07277** | **0.03357** |

**换成 diffusion 之后前段更好、尾部也更收——两头同时改善，没有 09-05 描述的取舍。**
所以 `pp_new` 相对 `pp_old` 的那个形状**不是 head 造成的**，
它落在 09-05 那轮同时动的另外两样（DINOv3→DINOv2 骨干、1 层 d512→8 层 d256 trunk）上，
或落在两者的交互上。**09-05 §7.2 的这条机制解释在本轮受控条件下被否证。**

注意这条否证有边界：`head_diff` 是"head + 时间频率基 + 积分步数"三合一（§2.1），
所以本轮能说的是"**换成 diffusion 那一整包不产生 09-05 描述的取舍**"，
不能说"**是 100 步而不是 10 步造成的**"。要拆开需要 `num_flow_steps` 扫描，本轮没做。

而且这 −3.0 % 的 raw 优势**在部署后消失**（0.03876，并列第三），
代价是推理慢 **4.43×**（`tables.md` 表 10）。**在上机口径上，这一整包换来的是 0。**

### 6.2 桥的代价与策略几乎无关，因为它换掉的不是策略的值，是策略的速度剖面

`send_next_action_chunk` 的桥（`strategies/core.py:479-503`）：取**实测**位姿作起点、
chunk 第 40 帧作终点、**起点速度固定为 0**、终点速度取第 40→41 帧差分，
画一条三次 Hermite S 曲线，**覆盖前 40 帧**。

离线口径下起点就是被示教的那一帧，所以**起点位置是对的**。错的是**起点速度**：
示教轨迹在锚点处一般不是静止的，桥强行令它静止。于是前段被系统性拖慢，
@1 上四个权重同时变差 28.6–36.0 %、@10 上同时变差 38.8–44.9 %。

**证据是这四个数彼此只差 6 个百分点，而四个权重的 raw 只差 3.0 %、deployed 只差 1.2 %。**
`filt_bridge_only` 与完整栈只差 1.0–2.4 个百分点，是同一件事的第二个证据：
**桥之前那三级做了什么，桥都会覆盖掉。**
本轮相对 09-05 的加强在于：**那轮的三个策略跨了策略类型、骨干和训练集，
这轮的四个权重只差一个字段，桥的代价仍然是同一个量级。**

### 6.3 为什么 `width512` 的 flat MAE 是平的而末端位置好 3.3 %

`width512` 的分组数（§4.3）：位置 **9.92 mm**（`base` 10.37，−4.3 %）、
夹爪 **0.0257**（0.0271，**−4.9 %**）、姿态 **3.57°**（3.52，**+1.4 %**）。
flat MAE 把米、弧度和 [0,1] 平均到一个数里，**位置和夹爪的改善被姿态的退化抵消**，
净得 −0.03 %。末端位姿那张表只看位置，所以它看得见这 −4.1 %。

**任何把三种单位平均到一个标量的指标都会抵消掉这类反向的分项差。**
这是 §4.3 那两张分组表存在的全部理由，也是本报告不用 flat MAE 单独下"加宽没用"结论的原因——
**准确的说法是：加宽在末端位置上买到了 3–4 %（读得出来），在 flat MAE 和上机口径上买到了 0。**

## 7. 建议

### 该部署什么

**这一轮不提供换权重的理由；`deploy_config_eef.yaml` 保持现状（`acteef_533`）。**
上机口径下四个新权重是 0.03849–0.03897，极差 1.2 %，判读线 1.70 %，**互相不可区分**；
末端位置 23.82–24.63 mm。作为刻度：`acteef_533` 在**同一批 anchor、同一套 filter、同一 horizon 50**
下的已发表数是 `policy_deployed` **0.03794** / 末端位置 **23.34 mm**（09-05 报告 §4.2/§4.3，
本轮未重跑），**仍然低于本轮四者中最好的 0.03849 / 23.82 mm**。

**如果一定要从这四份里挑一份继续做：挑 `depth1`。** 理由是成本，不是精度：
部署 MAE 四者最低（0.03849）、rmse 最低（0.08492）、tail 最低（1.67，raw）、
参数少 22.9 %、推理 **0.74×**。**它在精度上没有输给任何一个更大的模型，
而它是四个里最便宜的。**

### 该停止投入什么

1. **停止加宽。** `dim_model` 256→512：+65.3 % 参数、+44 % 推理时间、flat MAE −0.03 %、
   上机 −0.5 %（都在噪声里）、记忆倍数从 1.89× 涨到 **2.14×**、
   150 k 之后已经开始退化（§6.5）。**唯一读得出来的收益是末端位置 −3.3 %。**
   要继续加宽必须先解释为什么值 65 % 的参数量；本轮的数据不支持。
   若确实要保留加宽，**先把 `dim_feedforward` 一起从 1024 提到 2048**（恢复 4× FFN 比），
   本轮的 `width512` 是 2.0× 比例，不是等比放大（§2.1），**没有测过等比版本**。
2. **停止用 100 步 DDPM 换精度。** `head_diff` 的 raw −3.0 % 是真的，
   但部署后归零（−0.5 %，噪声内），代价是推理 **4.43×**（138 s vs 31 s，同一批 anchor 单次抽样）。
   **在一个 K=40 桥会覆盖掉前 40 步的部署栈里，为前段精度付 4 倍推理时间是不划算的。**
   `head_diff` 值得保留的是它的**正则化副作用**（§6.4：参数量不变而记忆倍数从 1.89× 降到 1.52×）——
   要的是这个的话，用 dropout / weight decay 去买会便宜得多，**这条没测过**。
3. **停止把工程力气放在这三个旋钮上，先处理 K=40 桥。** 本报告里最大的可控数是
   **+12.0 %~+15.5 %**，它属于桥；四个旋钮之间的全部差距是 **raw ≤3.0 % / deployed 1.2 %**。
   **投入产出比差 4–12 倍。** 具体两条（与 09-05 报告 §8 相同，本轮第二次确认）：
   - **桥的起点速度不该固定为 0。** 它现在强行让每个 chunk 从静止起步，而示教轨迹在锚点处
     一般不静止。用上一 chunk 末端速度（或实测速度）作起点速度，是一行改动，
     **不需要重新训练任何权重**。
   - **K=40 / 窗口 50 的比例应该复核。** 50 步里只有约 10 步是未被改写的策略输出；
     桥之前那三级 filter 的效果被完整覆盖（§5.1），它们目前是在为一段马上会被丢弃的轨迹做清理。
4. **停止在 200 k 这个点上比较 `head_diff` 和 `depth1`。** 两者到 200 k 仍在降
   （−5.1 % / −6.4 %，§6.5）。**要比它们，先各自训到收敛。**

### 还没测的（写"没测"，不写猜测）

- **闭环。** 全部是 teacher-forced 开环 chunk 评测，每个 anchor 从**被示教的**状态起步；
  机器人上 chunk N+1 从 chunk N 实际留下的位置起步。**本报告的任何数都不是成功率。**
- **交叉项。** 三个旋钮各测了一次单独改动，**没有** "1 层 + d512"、"diffusion + 1 层"
  这类组合。本轮只能读主效应，**读不了交互**。尤其：`depth1` 的省和 `width512` 的
  末端位置收益能不能同时拿到，**not measured**。
- **`num_flow_steps` / `num_inference_steps` 扫描。** `head_diff` 里"flow vs diffusion"
  和"10 步 vs 100 步"绑在一起（§2.1），**无法拆开**。10→20→50 步各评一次就能定论，
  一次评测 31 秒。
- **等比加宽（d512 + ff2048）。** 本轮的 `width512` FFN 比例是 2.0×，不是 4.0×。
- **用常规正则化复制 `head_diff` 的记忆抑制效果**（§6.4）。
- **`width512` 在 150 k 而不是 200 k 的上机表现。** 它的曲线最低点在 150 k（§6.5），
  但 150 k 那一列没有 `--seed-repeat`，**读不了小差**。
- **桥代价那 6 个百分点的权重间差别**（§5.2 的观察）。归因需要按锚点速度分层重算，没做。
- **末端 5 mm / 10 mm 容差列上的一切小差。** 判读线 29.0 % / 11.7 %（§3.3）。
- **`acteef_533` 在本轮同批 anchor 上的重跑。** §7 里引用的 0.03794 / 23.34 mm 来自
  09-05 报告，**本轮未重跑**（虽然 anchor 集合、filter、horizon 与本轮逐字相同）。
- **部署的图像路径。** 训练读视频帧，部署读 JPEG 且头部图用 `INTER_AREA` 缩放而训练用
  `INTER_LINEAR`。这是 harness 文档字符串明写的三条不可复现之一。
