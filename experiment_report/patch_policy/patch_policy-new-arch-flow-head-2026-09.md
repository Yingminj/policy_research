## 1. 结论

1. **在 raw 口径上，三个权重无法区分。** MAE `pp_old` **0.03417** / `acteef_h50` **0.03443** /
   `pp_new` **0.03462**，彼此相差 **0.7 %–1.3 %**；而本轮实测的采样噪声线是
   **1.70 %（flow）/ 2.00 %（diffusion）**（§3.2）。**全部差距都在噪声里。**
   null 对照同一批 anchor：`hold_state` 0.07266、`train_mean` 0.22729，三者都是 null 的 2.1 倍。
   **换架构在离线 raw 上没有买到任何可读的东西。**
2. **部署的 K=40 桥是比"换策略"大一个数量级的效应，而且它的代价几乎与策略无关。**
   `policy_raw → policy_deployed`：`acteef_h50` **+10.2 %**、`pp_new` **+12.6 %**、
   `pp_old` **+15.8 %**（0.03443→0.03794 / 0.03462→0.03897 / 0.03417→0.03955）。
   部署栈里其余四级累积下来是 **−1.8 %~−0.4 %**（小幅改善），**全部代价都在桥这一级**（§5.1）。
   损伤集中在桥覆盖的前 40 步：@10 上三个策略分别 **+37.5 % / +41.5 % / +40.9 %**，
   到 @50 摊薄成 +10.2 %/+12.6 %/+15.8 %。**三个策略的桥代价彼此只差 3 个百分点，
   而它们 raw 之间只差 1.3 %——这段误差主要由桥自己的形状决定，不由哪个策略产生的 chunk 决定**（§7.1）。
3. **上机口径（`policy_deployed`）下，`acteef_533` 仍然最好，新架构排第二。**
   `acteef_h50` **0.03794** < `pp_new` **0.03897**（+2.7 %）< `pp_old` **0.03955**（+4.2 %）；
   null `hold_state` 0.07266，三者分别是 null 的 1.92× / 1.86× / 1.84×。
   末端位置误差同序：**23.34 / 24.63 / 25.62 mm**（null 48.06 mm）。
   `pp_new` 对 `pp_old` 的 −1.5 % 在噪声内，**对 `acteef_h50` 的 +2.7 % 刚好压在噪声线上**——
   **可以说"没输"，不能说"赢了"。**
4. **新架构显著更会记训练集，而这一点没有换成 held-out 上的收益。**
   在训练时见过的 episode 上，`pp_new` MAE **0.01830**、`pp_old` **0.02937**——
   新架构好 **37.7 %**；到 held-out 上两者变成 0.03462 vs 0.03417，**新架构反而略差**。
   seen/unseen 比值 **1.89× vs 1.16×**（§6）。**这是过拟合的形状，不是能力的形状。**
5. **训练曲线的方向也相反：`pp_new` 已经收敛，`pp_old` 还没有。**
   `pp_new` 50k→200k 是 0.03662→0.03519→0.03471→0.03462，**100k 之后总共只降了 1.6 %，在噪声内**；
   `pp_old` 是 0.04092→0.03971→0.03580→0.03417，**到 200k 仍在降，100k→200k 降了 13.9 %**。
   **再加训练步数，更可能受益的是旧架构。**

**一句话：** **这次改动同时动了 head、视觉骨干和 trunk 三样东西，离线拿到的净效果是
"训练集拟合好 38 %、held-out 不变、上机比现役基线差 2.7 %"；而同一份数据说，
把工程力气投到 K=40 桥上的回报（10–16 %）是投到换架构上（≤4 %）的三倍以上。**

## 2. 评测集审计（在任何精度表之前）

### 2.1 这次改了什么——不是调参，是换了策略类型

`job.json` 的训练控制项**逐字段相同**（`probes/config_diff.txt` §1）：
同一个训练集 `batch_success_505_eef`（`train_config.json` 里连缓存哈希 `c7a7cd44` 都相同）、
seed 1000、200 000 步、batch 16、lr 5.5e-5 常数、无 scheduler、`image_transforms` 关闭。
**这是一次干净的 A/B。**

但差异不是"改了几个参数"。两个 `config.json` 属于**不同的策略类型**，
`probes/config_diff.txt` §3–§5 分三桶：

| 桶 | 数量 | 内容 |
|---|---:|---|
| 共有字段值变了 | **7 / 40** | `action_head` diffusion→**flow**、`vision_encoder` dinov3_patch→**dino_patch**、`dim_model` 512→**256**、`n_decoder_layers` 1→**8**、`dim_feedforward` 3200→**1024**、`type`、`vision_encoder_checkpoint` |
| 只有新策略有 | **15** | `num_flow_steps=10`、`time_injection=concat_mlp`、`state_injection=suffix_token`、`adaln_zero_init=true`、四个 `time_sampling_*`、两个 `time_*_period`、`use_relative_actions=false` 等 |
| 只有旧策略有 | **25** | 整套 VQ-BeT 机器（`vqvae_*` 4 个、`*_code_loss_weight` 2 个、`bet_softmax_temperature`、`gpt_*` 5 个…）、`diffusion_*` 4 个、`use_robot_state=true` |

**这不是一次受控消融。** head、视觉骨干、trunk 形状**同时动了三样**
（`probes/config_diff.txt` §9）。视觉骨干那一样特别值得点出：
`dino_patch` 解析成 **DINOv2 ViT-S/14，256 token/图，torch.hub 拉权重**；
`dinov3_patch` 解析成 **DINOv3 ViT-S/16+，196 token/图，读本地 checkpoint**。
两者都冻结。**新权重是把骨干从 DINOv3 换回了更老的 DINOv2，同时把每图 token 数从 196 提到 256。**

参数量：`pp_new` **32 249 486**、`pp_old` **38 091 550**、`acteef_533` **51 685 006**
（从 `model.safetensors` 头部读出，不是从 config 推的）。**新的是三个里最小的。**

> **`current_loss` 不能横比。** 0.016（`pp_new`）vs 0.018（`pp_old`）vs 0.053（`acteef_533`）
> 看着像同一把尺，其实一个是 flow 速度场的 MSE、一个是 DDPM 的 epsilon-MSE、
> 一个是 L1。**三个不同的目标，三个不同的量纲。** 这三个数在本报告里不作任何用途。

### 2.2 来源与污染：0 个 episode 被丢

`probes/splits.txt`：这 53 个 EEF episode 与关节版评测集是**同一批录制**
（`observation.velocity` 指纹 53/53 命中，episode-index 是恒等置换）。
按 `action` 数组的 SHA1 逐 episode 比对**七个数据集**：

```
batch_success_53_eval_data_eef  in batch_success_361      : 0
batch_success_53_eval_data_eef  in batch_success_505      : 0
batch_success_53_eval_data_eef  in batch_success_361_eef  : 0
batch_success_53_eval_data_eef  in batch_success_505_eef  : 0   <- pp_new / pp_old 的训练集
batch_success_53_eval_data_eef  in batch_success_533_eef  : 0   <- acteef_533 的训练集
```

三次主评测都传了 `--train-root batch_success_505_eef` **与** `--train-root batch_success_533_eef`，
harness 报 **572 个唯一训练 episode 指纹、丢弃 0 个**，
三个权重的 **anchor 集合因此逐个相同（2007 个）**——`summarise.py --selftest` 把这条写成断言。

### 2.3 OOD 率：0.24 %，只有一个通道

`probes/ood.txt`：以 `batch_success_505_eef` 的 MIN_MAX 统计箱为界
（两个 patch 权重的归一化器就是用它建的），40 132 帧里
**98 帧（0.24 %）至少有一个通道越界**，全部落在 `eef_r_x` 一个通道上，
**最大越界 0.0301 raw 单位（= 30.1 mm）**。其余 13 个通道越界 0 帧。
这个量级不会解释本报告里的任何差异。

### 2.4 对齐自检：三个 checkpoint 各一次，全过

`probes/check_alignment.txt`。这是唯一一个"错了还看着合理"的地方——
`action_delta_indices` 从 `1 - n_obs_steps` 起步，batch 里带着历史帧的动作。

| checkpoint | `n_obs_steps` | 动作窗口 | 计算出的 offset | 负对照 | 结论 |
|---|---:|---|---:|---|---|
| `pp_new` | 2 | −1..49 | 1 | 8/8 触发 | OK |
| `pp_old` | 2 | −1..49 | 1 | 8/8 触发 | OK |
| `acteef_533` | 1 | 0..99 | 0 | — | OK |

观测锚点 = 窗口**最新**一帧（部署的 Hermite 桥就是从这一帧的实测位姿起步的），
动作 offset = `n_obs_steps − 1`。**新策略类型没有改变这两条**。

## 3. harness：分叉、复现性、判读线

### 3.1 分叉六处，顶层一个字节没动

顶层 `eval_policy/offline_chunk_eval.py` **未修改**（`--selftest` 四组全过）。
run 目录里的副本有 6 处改动，完整 diff 见 `fork.diff`（+40 / −5）。
其中 **1–5 是 20260903 那次分叉的原样搬运**——它一直没有被合进顶层
（`grep ACTION_LAYOUT` 顶层无命中），而 09-04 报告的建议 2 要的就是它：
不修就没有部署列。第 6 条是本轮新增：

| # | 改动 | 不改会怎样 |
|---|---|---|
| 1–3 | 从动作名推出臂/夹爪划分，桥只改写臂列、clip 只作用在真实夹爪列 | 桥会 Hermite 改写第 12/13 列夹爪（`probes/deploy_stack.txt` §4：max\|Δ\| **1.434**）；clip 在宽度 14 时是**空操作**（max\|Δ\| **0.498**） |
| 4 | `--filter-ablation` 在宽度 < 16 跳过 `gripper_loops` | **直接崩**：`ValueError: Gripper indices [14, 15] are outside action width 14` |
| 5 | `evaluate()` 里调用并打印 `set_action_layout` | 上面三条拿不到划分 |
| 6 | `is_patch` 从 `== "patch_policy"` 改成 `in ("patch_policy", "patch_new_policy")` | **本轮主角直接崩**，见 §3.4 |

**分叉在 16-D 关节空间下与顶层逐位相同**（`probes/deploy_stack.txt` 末行断言 `True`），
关节侧的历史数字不受影响。

### 3.2 复现性：`acteef_533` 的两个已发表 MAE 逐位对上

`policy_raw` 完全不经过任何 filter，`act_eef` 是确定性 head，anchor / stride / batch_size / seed
与 09-04 那轮逐字相同，所以它的数必须逐位回来：

| run | horizon | 本轮 `policy_raw` mae | 09-04 报告 | |
|---|---:|---:|---:|---|
| `acteef_h50` | 50 | **0.03443** | 0.03443 | 逐位 |
| `acteef_h60` | 60 | **0.03689** | 0.03689 | 逐位 |

`hold_state` 也逐位对上（**0.07266** @h50 / **0.08216** @h60），anchor 2007、丢弃 0、
batch_size 全程 8。**加了部署列没有动到 raw 的任何一位。**

### 3.3 判读线：本轮四次抽样，比 09-04 的两次松得多

`--seed-repeat 3`（一共四次抽样：seed 0 + 三次重抽）。`act_eef` 是确定性 head，无需抽。

| 指标 | `pp_new`（flow）跨 4 次抽样的极差 | `pp_old`（diffusion） | 本报告采用的判读线 |
|---|---:|---:|---|
| mae | 0.00059（**1.70 %**） | 0.00067（**2.00 %**） | **2.0 %** |
| acc@0.25σ | 0.0042（0.53 %） | 0.0043（0.55 %） | 0.6 % |
| 末端位置均值 | 0.18 mm（0.87 %） | 0.19 mm（0.90 %） | 0.9 % |
| 末端 acc@5 mm（左臂） | 0.0146（**26.76 %**） | 0.0156（**29.83 %**） | **30 %** |
| 末端 acc@10 mm（左臂） | 0.0289（**11.73 %**） | 0.0454（**20.40 %**） | **20 %** |

> **这一栏直接更正 09-04 报告 §4.4。** 那份报告用**两次**抽样，给出的线是
> 末端 acc@5 mm **2.4–6.5 %**、acc@10 mm **4.7–9.8 %**。四次抽样测出来是
> **26.8–29.8 %** 与 **11.7–20.4 %**，**偏紧约 4 倍**。两次抽样估极差的问题很直白：
> 两点之间的距离系统性地低估一个分布的宽度。
>
> **后果：那份报告 §1.3 的论证不成立。** 它说三个 patch_policy 权重在 5 mm 上
> 输给 `hold_state`（0.042/0.035/0.049 vs 0.063），"差距是采样噪声的 6–12 倍，成立"。
> 按本轮的线（绝对噪声 ≈ 0.015），那些差距只有噪声的 **0.9–1.9 倍**，**读不出来**。
> 本轮**没有重测**那三个权重，所以这里说的是**它的论证不成立**，不是**它的结论是错的**——
> 那三个权重在 5 mm 上到底赢没赢 null，现在是 **not measured**。
> 本报告自己因此**不在 5 mm 那一列上读任何小差**（§4.3）。

### 3.4 踩到的坑：新策略类型会被顶层 harness 静默路由错

`patch_new_policy` 的 `predict_action_chunk`（`modeling_patch_new_policy.py:596-597`）
和 `patch_policy` 一样，是**从 `select_action` 的 deque 里重建输入**的，
离线批量跑永远填不满那个 deque。顶层 harness 用的是**精确字符串比较**
`cfg.type == "patch_policy"`，于是新类型掉进 ACT 分支、在空 deque 上炸。

**只看 `config.json` 看不出来**：`n_obs_steps`、`action_chunk_size`、`n_action_steps`
与 `patch_policy` 逐字段相同（§2.1 的"共有字段没变"那一桶）。

同一处还有第二个坑：**flow head 也抽噪声**——从 `torch.randn` 起步走 10 步 Euler
（`modeling_patch_new_policy.py:541,550`）。把它当确定性 head 处理，
两次跑会出不同的数而没人知道为什么。§3.3 的 1.70 % 就是这个噪声。

## 7. 机制：为什么是这些数

### 7.1 桥的代价与策略几乎无关，因为它换掉的不是策略的值，是策略的速度剖面

`send_next_action_chunk` 的桥（`strategies/core.py:479-503`）做的是：
取**实测**关节/位姿状态作起点、chunk 第 40 帧作终点、**起点速度固定为 0**、
终点速度取 chunk 第 40→41 帧的差分，画一条三次 Hermite S 曲线，**覆盖前 40 帧**。

在本报告的离线口径下，起点就是被示教的那一帧，所以**起点位置是对的**。
错的是**起点速度**：示教轨迹在锚点处一般不是静止的，而桥强行令它静止。
于是前段被系统性地拖慢，@1 上三个策略同时变差 26–32 %、@10 上同时变差 37–42 %。

**证据是这三个数彼此只差 4 个百分点，而三个策略的 raw 只差 1.3 %。**
如果桥的代价主要来自"策略给的第 40 帧终点不好"，
那么三个策略之间应该拉开与它们 raw 差距同量级的差异；实际没有。
`filt_bridge_only` 与完整栈只差 0.4–2.1 个百分点，是同一件事的第二个证据：
**桥之前那四级做了什么，桥都会覆盖掉。**

`pp_old` 的桥代价最高（+15.8 %）而 `acteef_h50` 最低（+10.2 %），
剩下这 5.6 个百分点的差别，本报告**只能观察，不能归因**——
要归因需要按锚点速度分层重算，本轮没有做（见"还没测的"）。

### 7.2 新架构为什么把训练集拟合得更好，held-out 上却没有

三样同时动的改动，两样都在**加拟合能力**：

- **trunk 从 1 层 × d512 变成 8 层 × d256**，并且带 AdaLN-zero 的条件注入
  （`adaln_zero_init=true`、`time_injection=concat_mlp`、`state_injection=suffix_token`）。
  参数量反而降了（38.1 M → 32.2 M），但**深度从 1 变成 8**——
  对同一批 505 个 episode，深度买到的是拟合，不是泛化。
- **视觉 token 从 196/图 提到 256/图**（DINOv2 ViT-S/14 vs DINOv3 ViT-S/16+）。
  两个骨干都冻结，所以这一步买到的是**更细的空间分辨率喂给一个更深的 trunk**。

第三样是 **head 从 100 步 DDPM 换成 10 步 flow matching**。
它在本报告里唯一可读的效果是 §4.1 的形状差异：
**`pp_new` 前段更好（@1 0.01658、@10 0.02092，三者最好），尾部更散（tail ratio 1.73，三者最高）。**
flow matching 的回归目标是一条常速路径的速度场，一次前向就定方向，
10 步 Euler 积分不做去噪意义上的纠错；DDPM 的 100 步每步都往数据流形上拉一次。
**前段准、尾部散，与"少步数、无纠错"是一致的**——但这是**一致，不是证明**：
本轮没有做 `num_flow_steps` 扫描，无法把这个形状单独归给步数。

**这三样合起来的净效果，held-out MAE 上是 +1.3 %（读不出来）、训练集上是 −37.7 %（读得出来）。**
这就是过拟合的定义。

### 7.3 为什么 flat MAE 看不见 §4.3 的两件事

`pp_new` 位置好 4.3 %、夹爪差 12.9 %，flat MAE 上净得 +1.3 %。
14 维里 12 维是位姿、2 维是夹爪，而夹爪的数值尺度（[0,1]，σ 大）
在 flat 平均里权重不小。**任何把毫米、弧度和 [0,1] 平均到一个数里的指标，
都会把这类反向的分项差抵消掉。** 这是 §4.3 那张分组表存在的全部理由。

## 8. 建议

### 该部署什么

**保持 `deploy_config_eef.yaml` 现状（`acteef_533`），不要因为本轮换权重。**
上机口径下它 0.03794，`pp_new` 0.03897（+2.7 %，刚过判读线）、`pp_old` 0.03955（+4.2 %）。
末端位置 23.34 vs 24.63 vs 25.62 mm。**新架构没有给出换权重的理由。**

### 该停止投入什么

**停止在"再换一个 head / 再换一个骨干"上投入，直到 K=40 桥被处理掉。**
本报告里最大的一个可控数是 **+10.2 %~+15.8 %**，它属于桥；
三个策略之间的全部差距是 **≤4.2 %**。**投入产出比差三倍以上。**
具体两条，按 §7.1 的机制排序：

1. **桥的起点速度不该固定为 0。** 它现在强行让每个 chunk 从静止起步，
   而示教轨迹在锚点处一般不静止。用上一 chunk 末端的速度（或实测速度）作起点速度，
   是一行改动，且**不需要重新训练任何权重**。
2. **K=40 / 窗口 50 的比例应该复核。** 现在 50 步里只有约 10 步是未被改写的策略输出
   （§5.2）。桥之前那四级 filter 的效果被完整覆盖（§5.1），
   它们目前是在为一段马上会被丢弃的轨迹做清理。

**也停止把 `patch_new_policy` 的 200 k 当成它的上限来读**——它 100 k 就收敛了（§6.1）。
它的问题不是训练不够，是泛化不动。

### 还没测的（写"没测"，不写猜测）

- **闭环。** 全部是 teacher-forced 开环 chunk 评测。每个 anchor 都从**被示教的**状态起步；
  机器人上 chunk N+1 从 chunk N 实际留下的位置起步。**本报告的任何数都不是成功率。**
- **桥代价那 5.6 个百分点的策略间差别**（§7.1）。要归因需要按锚点速度分层重算，没做。
- **受控消融。** head / 骨干 / trunk 三样同时动了。要把功劳或责任分给 flow head，
  需要"flow head + DINOv3 + 原 trunk"这个中间权重，**它不存在**。
- **`num_flow_steps` 扫描。** §7.2 关于"少步数导致尾部散"的说法是**一致性观察，不是证明**。
  10 → 20 → 50 步各评一次就能定论，一次评测 31 秒。
- **5 mm 末端容差列上的一切小差。** 判读线 30 %（§3.3）。
  `pp_new` 对 null 的 +9.5 % 是 **not measured**。要用这一列，抽样数还得再往上提。
- **09-04 报告 §1.3 涉及的那三个权重**（`pp_eef_state` / `pp_eef_nostate` / `pp_eef_act5`）
  **在 `--seed-repeat 3` 下的 5 mm 命中率**。本轮更正了判读线（§3.3），但没有重测它们，
  所以那三个权重"在 5 mm 上输给 null"现在既未证实也未证伪。
- **部署的图像路径。** 训练读视频帧，部署读 JPEG 且头部图用 `INTER_AREA` 缩放而训练用
  `INTER_LINEAR`。这是 harness 文档字符串明写的三条不可复现之一。
- **`acteef_533` 的中间训练步。** 曲线只对两个 patch 权重跑了。
