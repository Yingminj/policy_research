## 1. 结论

1. **尺子没变。** 四个权重、五条 horizon 配置，十个已发表标量（mae / rmse / norm_mae /
   norm_rmse / @1 / @10 / @25 / @50 / 两个 null）**全部逐位复现**，anchor 数 2007、
   丢弃 0 也一致。两个新指标是**加列，不是改列**。
2. **两个指标的开关方式是不同的，这是设计不是疏漏。** `acc@τ` **永远算**——它是每
   batch 一次广播比较，比"要不要算"的那个分支还便宜；**末端位姿误差按适用性自动开**——
   它要一遍正运动学或一次位姿切分，所以只在动作空间支持时打开，否则打印原因跳过（§2）。
3. **一个 MAE 看不见的结论：在 5 mm + 0.01 rad 容差上，三个 patch_policy 权重全部输给 null。**
   `hold_state` 左臂 0.063，三个权重是 0.042 / 0.035 / 0.049——**同时它们的平均位置误差
   只有 null 的一半**（21.7 / 23.0 / 21.8 mm vs 41.1 mm）。差距是采样噪声的 6–12 倍（§4.4）。
   直白的读法：**这三个权重从不真正"到位"，它们只是处处差不多近。**
4. **`acteef_533` 是四个里唯一在紧容差上赢过 null 的权重**（0.093 / 0.101，null 0.063），
   而且它的前段优势比 09-03 报告的 @1 显示的更大：acc@0.25σ 从 **0.937** 起步，
   三个 patch_policy 是 0.843–0.880。**K=40 的桥盖掉的正是一段"94 % 的步子在容差内"的轨迹**，
   这给 09-03 报告 §6.2 的机制论证补了一个独立的量。
5. **`pp_eef_act5` 与基线在紧容差上排序翻转。** 5 mm 上 act5 **0.049 > 基线 0.042**
   （差距是噪声的 3–7 倍），50 mm 上 act5 **0.949 > 基线 0.934**，姿态也更好（6.76° vs 6.92°）——
   但 10 mm 上基线反超（0.214 vs 0.185）。09-03 报告把 +2.0 % 的 MAE 差称为"弱结论、不要单独引用"，
   这里给出更强的说法：**这两个权重不是被排序，是形状不同**——act5 两头好、中间差，
   与 §4.3 的 tail ratio（1.60 vs 1.65）是同一件事的第二个独立证据。
6. **新指标自己的判读线**（§4.4）：`acc@τ` 的两次抽样差 ≤ 0.005 绝对 / 0.7 % 相对；
   末端 acc@τ 在紧容差上要松得多，5 mm 处 2.4–6.5 %、10 mm 处 4.7–9.8 % 相对。
   **10 mm 那一列是本报告里最不稳的一列，不要在它上面读小差。**

**一句话：** **两列新指标没有改变 09-03 报告的任何排序，但它们指出一件 MAE 结构上看不见的事——
`acteef_533` 会"到位"，三个 patch_policy 只会"靠近"；上机结论因此比 09-03 更强，不是更弱。**

## 2. 两个指标是什么，以及为什么开关方式不一样

### 2.1 `acc@τ`：永远算，因为它比不算还便宜

定义：在有效的 (step, joint) 对里，`|pred − gt| ≤ τ` 的比例。
τ 取**每个关节自己动作标准差的倍数** `(0.1, 0.25, 0.5, 1.0)·σ_j`，不是一个统一的弧度值——
EEF 动作向量里 12 维位姿是米/弧度、2 维夹爪是 [0, 1]，
**"在 0.05 以内"在这两组维度上根本不是一件事**。σ 取自 checkpoint 自己的 postprocessor，
与 `norm_mae` 用的是同一把尺。

实现代价是每 batch 一次 `(err.abs() <= thresholds)` 广播比较，
张量形状 `(n_tau, B, H, J)`，在本轮配置下是 4×8×50×14 个 bool。
**这比"要不要算它"的那个分支更便宜**，所以它没有开关：
一个永远在报告里的指标，是没人需要为了拿它而重跑 harness 的指标。

报出三列：`acc_at_tau`（总体）、`acc_at_tau_at_horizon`（按 horizon 截断，看衰减）、
`acc_at_tau_per_joint`（看是哪几个维度落在容差内）。

### 2.2 末端位姿误差：按适用性自动开，因为它真的要算

这一列要么一遍正运动学、要么一次位姿切分，所以**它是有条件的**——
条件不是"谁想看"，而是"这个动作空间支不支持"。`resolve_eef()` 按动作维度名字分派：

| 动作空间 | 走哪条路 | 本轮 |
|---|---|---|
| 14-D EEF（`eef_l_x` … `gripper_R`） | **直接切分，不做运动学** | **是这一条** |
| 16-D / 54-D 关节（`Joint1_L` …） | MJCF 正运动学 | 不适用 |
| 8-D 单臂（`joint_1.pos` …） | 跳过，打印原因 | 不适用 |

本轮四个权重全在 EEF 空间，动作向量**本身就是位姿**，所以正运动学不只是多余、是**不适用**——
MJCF 链要的是关节角。harness 打印的是 `eef pose error: eef-space (direct, no kinematics)`。

关节空间那条路复用 `robot_data_platform/tool/tr_joint_to_eef.py` 的
`MjcfForwardKinematics`（按路径加载，与部署重写同一套做法），MJCF 取
`Apex_Deploy_new/robot_node/marvin_description/mjcf/matrix/m6_696.xml`——
**注意 `tr_joint_to_eef.DEFAULT_MJCF` 指向一个本 checkout 不存在的兄弟路径，
那是个死默认值**，harness 里写死了正确位置。

**姿态误差是四元数测地角，不是欧拉角之差。** rpy 相减在 ±π 处会绕回，
而且在万向锁附近病态——腕关节恰好整天待在那里。自检里钉住了这一点：
yaw = π 与 yaw = −π 是同一个旋转，测地角给 0，欧拉相减给 6.283。

**位置误差是欧氏距离 ‖Δp‖，不是逐轴平均。** 这与 09-03 报告 §4.4 的 mm 列
**不是同一个量**：那一列是 `mae_per_joint` 在 x/y/z 上的平均，回答"一个坐标错多少"；
这一列回答"夹爪离该在的地方多远"。两者的比值在各向同性高斯误差下**恰好是 2**
（χ₃ 均值 2σ√(2/π) 比半正态均值 σ√(2/π)），本轮五条 run 实测 **2.01–2.03×**（§4.2）——
**换算稳定，但两列不能混在一张表里不加标注。**

### 2.3 `acc@τ` 也在末端空间上重报一次

同一个累加器换一组阈值即可，阈值改成**绝对的米和弧度**而不是 σ 的倍数：
`(5 mm, 0.01 rad)`、`(10 mm, 0.025 rad)`、`(25 mm, 0.05 rad)`、`(50 mm, 0.1 rad)`。
毫米就是毫米，与动作标准差无关。**§1.3 与 §1.4 全部出自这一列。**

### 2.4 harness 改的是顶层文件，不是又开一个分叉

09-03 报告的做法是**分叉**（`fork.diff`，72 行），并明确写下"顶层
`offline_chunk_eval.py` 一个字节没动"。本轮相反：**改的就是顶层文件**
（`runs/20260904_acc_tau_eef_pose/harness.diff`，+459 / −7 行）。

理由只有一条，而且是可检验的：**十个已发表标量逐位复现**（§3）。
新增的全是新键，没有一个旧键的算法被动过。唯一改到既有代码路径的是
`overall[k].hit_sum` 的跨数据集合并——那是新键自己的合并，旧键的
`abs_sum / sq_sum / count` 三行原样未动。

**但顶层的 16-D 硬编码没有被修。** 09-03 报告 §3.4 列的四条
（桥只该重写非夹爪列、夹爪 clip 该作用在真实夹爪列、`gripper_loops` 在宽度 < 16 时会
`ValueError` 直接崩、臂/夹爪划分该从动作名推出）**至今只存在于那个 run 目录的分叉里**。
本报告因此只能跑 `--filters none`，也因此没有部署列。**这是本轮最该被合并上来的一件事。**

自检：`python offline_chunk_eval.py --selftest` 现在跑四组，
新增 `eef slice`（含 π/−π 绕回、欧氏距离、左右不串台、reshape 不串台）
与 `eef pose error`（FK 链的左右隔离与单铰链转角）。

## 5. 机制：13 mm 的底噪

`mean_per_horizon` 把 §4.3 第 1 点的原因摊开（左臂位置，mm）：

| | step 0 | step 10 | step 40 | step 49 |
|---|---:|---:|---:|---:|
| `pp_eef_state` | **13.34** | 16.83 | 26.85 | 28.60 |
| `acteef_533` (h50) | **9.18** | 13.74 | 23.30 | 25.32 |
| *null* `hold_state` | 16.10 | 26.93 | 56.00 | 63.58 |

**`pp_eef_state` 在 chunk 的第一步就已经差 13.34 mm，而 5 mm 的容差比这小两倍半。**
它之后的整条曲线都在这条底噪之上，所以紧容差上它几乎不可能有命中；
`hold_state` 的均值虽然从 16.10 一路涨到 63.58（比它差得多），
但它的分布是**双峰**的——不动的帧上接近 0、动的帧上极大——
于是在 5 mm 上仍然攒下 6.3 % 的命中。
`acteef_533` 起步 9.18 mm，**低于 10 mm 容差**，这正是它 §4.3 两列领先的来源。

**这解释了为什么 MAE 看不见这件事**：MAE 是一阶矩，对"多数帧中等偏差"与
"一半帧极准一半帧极差"给同一个数；`acc@τ` 直接问分布左尾有多少质量。
09-03 报告 §4.3 的 tail ratio 已经在问一个相关的问题（右尾），
`acc@τ` 补上的是**左尾**。

   §2.4 的四条修复至今只在 run 目录里；只要它们不上来，任何新指标都只能在
   `--filters none` 下报告，而 09-03 的头号发现（K=40 桥让四个权重全部变差 3–8 %）
   **恰恰只在部署列里可见**。本报告最该被接上去的就是这一段：
   **`acteef_533` 前 40 步有 93.7 % 的步子在 0.25σ 容差内，而桥盖掉的就是这 40 步**——
   这个数目前只有 raw 版本，没有"过完桥之后还剩多少"。
3. **5 mm 命中率应该进 `patch_policy-matrix.md` 的常规列。** 它是本轮唯一一个
   **改变了权重之间定性判断**的指标（§1.3 / §1.5），而且它免费。
4. **不要在 10 mm 那一列上读小差。** 它的采样噪声到 9.84 %，是本报告里最松的一条线（§4.4）。
   要用它，得先把 `--seed-repeat` 的抽样数从 1 提到 3 以上。
