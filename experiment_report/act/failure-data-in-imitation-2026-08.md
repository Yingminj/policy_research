# 加入失败/纠错数据为什么反而更差？——361 成功 + 36/72 失败三组权重的实测复盘

> 撰写日期：2026-08-18
> 数据：`/mnt/robot_platform/datasets/tidy_up_stationery_le/{batch_success_361, batch_success_361_fail_36, batch_success_361_fail_72}`
> 权重：`/mnt/robot_platform/jobs/act_tidy_up_stationery_le_batch_success_361{,_fail_36,_fail_72}_*`
> 复现脚本：[`experiment_report/scripts_fail_data/`](./experiment_report/scripts_fail_data/)
>
> **前置声明（重要）**：磁盘上**没有任何 rollout 成功率记录**——三个 job 的 `env_eval_freq` 都是 0，
> `/mnt/robot_platform/` 下没有评测目录。所以本文所有数字都是**离线**指标
> （数据统计 + teacher-forcing 开环 chunk 误差 + 遮挡消融）。
> "加了失败数据后表现变差"这个结论本身目前**只有主观观察支撑**，没有闭环数字。
> 这不是吹毛求疵：§4 会看到，离线指标上"变差"几乎看不出来，
> 所以**伤害必然发生在闭环**，而闭环恰恰是你现在唯一没有测的东西。补这个数是第一优先级（§6.4）。

## 0. 一页结论

**该不该加？——以现在这种形式，不该。** 不是因为"失败数据有毒"，
而是因为你加进去的东西同时携带了三样与"纠错"无关的负载，其中任何一样单独都足以抵消收益：

| # | 加进去的东西 | 实测证据 | 严重度 |
|---|---|---|---|
| 1 | **一个独立的采集会话块**（08-18 单场次 1h43m，背景有椅子/胶带卷，物体摆放随机化明显更弱） | 背景亮度 std 5.9 vs 成功集 25.4；单标量可 66.9% 分开两集 | **最高** |
| 2 | **同一视觉状态下 18× 的条件动作分歧**（同一 state 邻域，未来 100 步动作 MAE 0.065 vs 0.0036 rad） | §3.1 | 高 |
| 3 | **系统性更长的 episode**（994 vs 828 帧），帧级采样下比例被放大 | 名义 16.6% episode → 实际 18.5% 帧 | 中 |

而 §3.3 那个遮挡消融是整份报告里最扎眼的一条：

> 把头相机**最上面 120 行（纯背景：地面、椅子、坐在桌后的人）**涂灰，
> 开环动作误差涨到 **2.52×**；
> 把**中间 120 行（桌面、笔筒、两支笔——真正的任务信息）**涂灰，只涨到 **2.00×**。
>
> **策略对"与任务无关的背景像素"的依赖，比对"物体本身"还强。**

在这个前提下，"新增一个背景明显不同的会话块"不是加数据，是**给策略递了一个免费的模式选择捷径**：
它可以用背景判断"我现在在成功场次还是纠错场次"，从而把两个互相矛盾的模式都拟合到 0.012 rad
（§4 实测确实如此）。训练时天衣无缝，部署时那个捷径特征既不属于成功场次也不属于纠错场次，
模式选择就变成随机的——而 `n_action_steps=100` 且 `temporal_ensemble_coeff=None`，
**一次选错模式 = 3.33 秒的开环盲走**。

**比例怎么定？** 见 §6.2。一句话版本：
在**没有条件化**的 ACT 上，文献里 1:1 和 1:4 都测过，naive 混合的收益是 **+0.6 个百分点**（统计噪声级）；
你现在这个 9%/16.6% 落在"稀释到看不出效果、但足够引入一个会话块"的最差区间。
要么降到 ≤5% 帧**且只保留纠错片段**，要么加条件化后拉到 20–50% 并按 IWR 加权。中间地带没有价值。

**采集要注意什么？** §6.3 有 10 条清单。最重要的三条：
**不要单独攒一个失败批次**（要与成功数据同场次交替采）、
**把标签写进数据**（现在六个数据集的 task 全是 `"Unspecified task"`）、
**失败数据要来自策略自己的失败**而不是人工演的失败。

## 1. 事实核对：这三个数据集和三次训练到底是什么

### 1.1 数据集组成

| 数据集 | episodes | frames | 平均长度 | 失败占比(ep) | 失败占比(**帧**) |
|---|---:|---:|---:|---:|---:|
| `batch_success_361` | 363 | 300,689 | 828.3 | — | — |
| `batch_success_361_fail_36` | 399 | 336,477 | 843.3 | 9.02% | **10.64%** |
| `batch_success_361_fail_72` | 435 | 368,957 | 848.2 | 16.55% | **18.50%** |
| `batch_fail_36`（单独） | 36 | 35,788 | 994.1 | | |
| `batch_fail_72`（单独） | 72 | 68,268 | 948.2 | | |

核对结论（全部经脚本验证，见 `locate.py` / `phase.py`）：

- **`batch_fail_36` 是 `batch_fail_72` 的前 36 条**（源 bag 目录名逐条相同）。所以两次实验是**嵌套**的，
  这一点做得很好，是干净的比例消融。
- **失败 episode 在合并集里位于 index `0..35` / `0..71`（前置，不是追加）**。
  这意味着你可以用 `--dataset.episodes` 直接切出纯成功子集（`72..434`），
  不需要重新转换数据——这对 §6.4 的对照实验很有用。但这件事没有记录在任何 manifest 里，是我反查出来的。
- `batch_success_361` = `batch_7`(163) + `batch_8`(200) = 363 条。
  → **不存在真正的留出成功集**。§4 里我用 `batch_1`（08-07，63 条，三次训练都没见过）当跨场次探针。
- **六个数据集的 task 字符串全部是 `"Unspecified task"`，`total_tasks = 1`。**
  策略在输入端**完全无法区分**一条轨迹是成功演示还是纠错演示。这是所有问题的总闸门。

### 1.2 采集时间：失败数据是一个独立的会话块

| 批次 | 源 bag 时间跨度 |
|---|---|
| `batch_7`（成功，163 条） | 26-08-12 15:39 → 26-08-14 17:44（跨 3 天） |
| `batch_8`（成功，200 条） | 26-08-17 14:07 → 26-08-17 17:23 |
| `batch_fail_72` | **26-08-18 15:24 → 26-08-18 17:07（单场次，1 小时 43 分）** |

72 条失败数据来自**一个下午、一次连续坐班**。这是 §3.3 全部问题的来源。

### 1.3 三次训练

| job | steps | epochs | batch | node | 末端 loss | 200k ckpt |
|---|---:|---:|---:|---|---:|:--:|
| `..._batch_success_361_2026-08-17_12-42-42` | 200,000 | 10.64 | 16 | gpu01 | 0.042 | ✓ |
| `..._fail_36_2026-08-18_05-11-55` | 250,000 | 11.89 | 16 | gpu05 | 0.040 | ✓ |
| `..._fail_72_2026-08-18_06-09-55` | 250,000 | 10.84 | 16 | gpu01 | 0.041 | ✓ |

两个混淆项，都可以消掉：

1. **步数不一致（200k vs 250k）**。好消息是两个 fail run 都存了 `checkpoints/200000/`，
   §4 全部在 200k 对齐评测（同时也报了 250k 供参考）。
2. **训练 loss 三者几乎相同（0.042 / 0.040 / 0.041）**。
   这不是"没问题"的证据，而是**"训练 loss 在这个问题上完全没有信息量"的证据**——
   模型把两种互相矛盾的模式都拟合到了同一水平（§4 会看到具体怎么做到的）。
   **不要再用 loss 判断加数据有没有用。**

策略配置（三次相同）：

```
ACT, chunk_size=100, n_action_steps=100, temporal_ensemble_coeff=None,
use_vae=True, latent_dim=32, kl_weight=10.0, n_obs_steps=1,
vision_backbone=resnet18, lr=1e-5 (backbone 同), 3 相机 (top/wrist_L/wrist_R) 480x640
```

`n_action_steps=100` + 无 temporal ensemble → **每次推理后开环执行 3.33 秒**。
`n_obs_steps=1` → 策略是**单帧马尔可夫**的，输入里没有"我刚才已经试过一次"的信息。
这两条在 §3.4 / §3.5 会具体算账。

## 2. 这些"失败"数据到底失败在哪

先搞清楚被加进去的是什么行为，否则讨论比例没有意义。

### 2.1 不是重抓——夹爪开合次数完全相同

| 数据集 | 每 episode 夹爪翻转次数 mean / median / p90 |
|---|---|
| `batch_success_361` | 4.04 / 4.0 / 4.0 |
| `batch_fail_72` | 4.08 / 4.0 / 4.0 |

4 次 = 两支笔 × (闭合 + 张开)。**失败 episode 里没有多余的抓取尝试。**
所以这批数据不是"抓空了→重抓"，也不是"抓掉了→捡起来"。

### 2.2 多出来的时间在"第一次抓取前的接近段"

以夹爪事件切分阶段（中位数，单位帧 @30fps）：

| 阶段 | 成功 | 失败 | 差 |
|---|---:|---:|---:|
| 起始 → 第 1 次闭合（**接近段**） | 107 | **167** | **+56%** |
| 第 1 次闭合 → 第 2 次事件 | 128 | 157 | +23% |
| 中段（搬运/放置） | 331 | 345 | +4% |
| 第 3 → 第 4 次事件 | 94 | 105 | +12% |
| 收尾 | 142 | 165 | +16% |
| **总计** | **810** | **941** | **+16%** |

结论：**"失败与纠错"实际表现为"接近目标时对不准 → 中途修正 → 一次抓取成功"**，
纠错发生在**接近段**，而接近段恰恰是成功数据说"直着过去"的地方。冲突正面撞上。

抽查末帧（`fail_last8.png` / `succ_last8.png`）：**失败 episode 最终都完成了任务**（笔进筒、手臂收回）。
所以这批数据是**纠错演示（failure-then-recovery）**，不是终止于失败的负样本。
这点是好的——如果是终止于失败，问题会严重得多。

### 2.3 失败会话的状态分布更窄、更偏

`action` 各维标准差（左臂前 6 维，rad）：

| 维度 | 成功集 | 失败集 | 比值 |
|---|---:|---:|---:|
| Joint1_L | 0.331 | 0.217 | **0.66** |
| Joint3_L | 0.215 | 0.140 | **0.65** |
| Joint4_L | 0.212 | 0.156 | 0.74 |
| Joint6_L | 0.284 | 0.134 | **0.47** |
| 均值偏移 Joint4_L | −2.015 | −1.821 | +0.19 rad |

外加每步动作增量 `|ΔA|` 均值 0.0548 → **0.0407**（更慢、更犹豫）。

**失败场次的物体摆放随机化明显弱于成功场次**（左臂工作空间只覆盖成功集的 47–74%），
同时整体动作更慢。这两条都会被 BC 原样学走。

平均图对比（`meanimg.png`）把这件事画得很直白：
成功集的平均图里**机械臂被平均糊掉了**（位姿高度多样），
失败集的平均图里**机械臂是清晰的**（长时间停在同一个位形），且橙色笔在固定位置留下清晰残影。

### 2.4 一个被排除的嫌疑：归一化统计漂移

ACT 用数据集 mean/std 做 `MEAN_STD` 归一化，所以要检查加数据后统计量漂了多少：

| | 最大偏移 (Δmean / 原 std) | std 比值范围 |
|---|---|---|
| `+fail_72` vs `361` | **0.17σ**（Joint4_L），其余 15 维全部 < 0.08σ | 0.939 – 1.023 |

**归一化漂移不是原因**，可以从嫌疑名单划掉。

## 3. 五个可测的伤害机制（按证据强度排序）

### 3.1 条件动作分歧：同状态下 18×

方法（`conflict.py`）：把 state 按成功集 std 归一化，对每个失败帧在成功集中找最近邻，
比较两者**未来 100 步动作序列**的 MAE。对照组是"成功帧 → 成功集最近邻"。

| 查询 | 最近邻距离 (中位数, σ) | 最近邻距离 p90 | 匹配上时未来 100 步 chunk MAE (rad) |
|---|---:|---:|---:|
| 成功帧 → 成功集 | **0.040** | 0.345 | **0.0036** |
| 失败帧 → 成功集 | **0.687** | 1.059 | **0.0651**（限 d<0.5σ, n=507） |

两个数字都要读：

1. **成功集自身的最近邻距离是 0.040σ**——361 条演示基本是互为副本的窄管道。
   在这样一个低多样性数据集上，任何新分布都是大扰动。
2. **在两者确实重合的状态上，未来动作分歧是成功集内部的 18 倍。**
   这就是"条件动作分歧"（action divergence，Belkhale et al. NeurIPS 2023 的核心量）的直接测量。

ACT 的解码器在推理时取 `z=0`（先验均值）以获得确定性行为。
当同一个观测对应两个差异 18× 的动作模式，而模型又无法从观测中区分它们时，
L1 损失的最优解是**条件中位数**——表现为"到了该抓的位置反而悬停"。

### 3.2 离流形：失败状态大多不在成功流形上

上表第一列：失败帧到成功集的最近邻中位距离 0.687σ，p90 1.059σ。
即**大部分失败帧在成功数据里根本没有对应点**。
它们不是在"补上成功数据没覆盖的恢复区域"（那样是好事），
而是在"另一个会话的另一片工作空间里"（§2.3）。这两件事在数字上长得一样，但价值完全相反。

### 3.3 会话块 = 视觉捷径 ← **最关键的一条**

**(a) 失败集在视觉上是一个近乎常量的块。** 头相机顶部背景带（桌面之上，纯地面/椅子/人）的平均亮度：

| | mean | **std** | 单标量分离准确率 |
|---|---:|---:|---:|
| 成功集 | 88.8 | **25.4** | — |
| 失败集 | 75.9 | **5.9** | **0.669** |

成功场次背景一直在变（有人走动、有人坐在桌后）；
失败场次背景几乎不变（一把黑椅子固定停在那儿，左上角多一个胶带卷）。
**一个标量就能 67% 分开两集，一个 ResNet-18 能做到多少不用猜。**

**(b) 而这个策略恰恰极度依赖背景像素。** 遮挡消融（`eval4.py`，基线权重，成功集，等大小 120 行条带）：

| 遮挡区域（头相机 480 行） | 开环 chunk L1 (rad) | 相对干净输入 |
|---|---:|---:|
| 不遮挡 | 0.0117 | 1.00× |
| **上 0–120 行（纯背景：地面/椅子/人）** | **0.0295** | **2.52×** |
| 中 180–300 行（桌面 + 笔筒 + 两支笔） | 0.0234 | 2.00× |
| 下 360–480 行（两条机械臂） | 0.0264 | 2.26× |
| 整个头相机涂灰 | 0.0627 | 5.36× |
| wrist_L 涂灰 | 0.0479 | 4.09× |
| wrist_R 涂灰 | 0.0379 | 3.24× |

**遮挡"与任务无关的背景"比遮挡"任务物体所在的桌面"伤害更大（2.52× vs 2.00×）。**

（诚实的限定：任何遮挡都会把输入推出分布，所以这些倍数是依赖强度的**上界**；
但三个条带尺寸相同、退化方式相同，**相互之间的比较是公平的**，
而排序"背景 > 手臂 > 桌面物体"是稳定的，`+fail72` 权重上排序完全一致
（2.13× / 2.02× / 1.84×）。）

**(c) 合起来是什么意思。** 策略的头相机通路主要锚定在**场景/场次上下文**而非物体上。
于是当你新增一个背景可辨识的会话块时，模型不需要解决 §3.1 的动作冲突——
它只要学会"看到椅子 → 走慢速修正模式；看到有人坐着 → 走直冲模式"。
§4 的数字证明它**确实做到了**：`+fail72` 在两个互相矛盾的模式上都达到 0.012 rad。

训练完美，部署崩溃：真实部署时的背景既不是 08-17 那把空椅子也不是 08-18 那把黑椅子，
捷径特征处于 OOD，模式选择变成掷骰子。

### 3.4 一次选错模式 = 3.33 秒开环盲走

`n_action_steps=100`、`temporal_ensemble_coeff=None`：
策略每次推理输出 100 步并**全部执行完**才重新观测。
在 §3.1 的冲突点上，如果模式选错（或者输出两模式的均值），
代价不是一帧的抖动，而是 **3.33 秒的错误轨迹**，且期间没有任何视觉反馈能纠正。

这是一个**放大器**，不是独立原因，但它决定了 §3.1–3.3 的后果是"轻微抖动"还是"整条 episode 报废"。
它也解释了为什么 §4 的开环指标只掉 10% 而实际观感"差很多"：
开环指标是 teacher-forcing 的，看不到复合误差。

### 3.5 非马尔可夫性（次要）

"我已经试过一次了"这个信息在 `n_obs_steps=1` 下不可观测。
量化（`revisit.py`，同一 episode 内相距 >1.5s 且 state 距离 <0.15σ 的状态对）：

| | 状态重访率 | 重访点上的动作 chunk MAE (rad) |
|---|---:|---:|
| 成功集 | 0.0015 | 0.0436 |
| 失败集 | 0.0011 | **0.0703（1.6×）** |

有效应，但只有 1.6×，远小于 §3.1 的 18×。
**这批数据的冲突主要是"跨 episode / 跨会话"的，不是"同 episode 内历史依赖"的。**
所以"加历史帧"不是这个问题的主药方（虽然对真正的重抓型纠错会是）。

## 4. 权重实测：伤害在哪、不在哪

方法（`eval2.py` / `eval3.py`）：三个 checkpoint 在 200k 步对齐，
用 LeRobot 0.6 的 pre/post processor 做正确的归一化/反归一化，
测 teacher-forcing 下 100 步动作 chunk 的 L1 误差（单位 rad，反归一化后的真实关节量）。

> 踩坑记录：`ACTPolicy.predict_action_chunk()` 在 0.6 里**不做归一化也不做反归一化**，
> 必须自己套 `make_pre_post_processors(cfg, pretrained_path=...)`。
> 直接调会得到 ~0.9 rad 的垃圾数字（比真值大 60 倍）。

### 4.1 主表（200k 对齐）

| checkpoint | 成功集 | 失败集 前36条 | 失败集 后36条 | `batch_1`(08-07, 三者皆未见) |
|---|---:|---:|---:|---:|
| `succ361` 200k | **0.0117** | 0.0812 | 0.0775 | 0.1412 |
| `+fail36` 200k | 0.0129 | *0.0121*（已见） | **0.0516**（未见） | 0.1345 |
| `+fail72` 200k | 0.0129 | *0.0121*（已见） | *0.0125*（已见） | 0.1305 |
| `+fail36` 250k | 0.0117 | — | — | 0.1356 |
| `+fail72` 250k | 0.0118 | — | — | 0.1289 |

*斜体 = 训练集内拟合，非泛化。*

### 4.2 五条读数

**(1) 加失败数据对成功分布的拟合损伤 ≈ +10%，且到 250k 完全消失。**
0.0117 → 0.0129（200k），到 250k 回到 0.0117/0.0118。
**这不是容量问题，也不是"被稀释"问题。** 排除掉一个常见猜测。

**(2) 模型把两个 18× 冲突的模式都拟合到了 0.012 rad。**
`+fail72` 在成功集 0.0129、在失败集 0.0121/0.0125——**一样好**。
在 §3.1 已证明这两个模式在 state 空间上重叠且动作差 18× 的前提下，
模型能同时拟合两者，**只可能是找到了某个观测线索来做模式选择**。
结合 §3.3(b)（背景比物体更重要）和 §3.3(a)（失败集背景近乎常量），
最省力的候选线索就是场次背景。这是本报告最重要的推断。

补充证据：把背景带涂灰后，`+fail72` 在失败模式上的误差涨 1.39–1.47×
（0.0121→0.0178，0.0125→0.0174），说明背景确实参与了该模式的预测；
在成功模式上涨 2.13×（0.0129→0.0275）。两个模式都吃背景。

**(3) 36 条失败数据对失败模式的泛化是失败的。**
`+fail36` 在见过的 36 条上 0.0121，在没见过的另外 36 条上 **0.0516（4.3×）**。
对比：363 条成功数据在成功分布上是 0.0129。
**纠错行为的内在多样性远高于名义任务行为，36 条远不足以覆盖。**
（它确实把基线的 0.0775 降到了 0.0516，降了 33%，但离"学会了"差一个量级。）
这条直接否定了"少加一点失败数据就能学会恢复"的想法。

**(4) 跨场次泛化对所有权重都是灾难，加失败数据略有帮助。**
`batch_1`（08-07 的成功数据）上全部是 0.13–0.14 rad，
是同分布误差的 **11 倍**。三个权重都没能跨过 11 天前的那个场次。
加失败数据让它从 0.1412 降到 0.1305（−7.6%）——方向是对的，
因为多了一个场次就多了一点场次多样性。但 −7.6% 相对于 11× 的鸿沟毫无意义。
**这条数字的真正含义是：你的策略对场次变化极度脆弱，而这正是 §3.3 的独立佐证。**

**(5) 离线指标看不见你观察到的退化。**
成功分布上最多 +10%（且 250k 归零），跨场次上甚至更好。
**如果闭环确实明显变差，那么伤害 100% 发生在开环指标测不到的地方**——
即复合误差 + 模式选择 + 3.33 秒开环执行（§3.4）。
这反过来支持"模式选择在部署时失效"这个解释，
因为其他机制（拟合能力、归一化漂移、容量竞争）都会在开环指标上留下痕迹，而它们没有。

**文献的共识非常清晰，而且和你的实测严丝合缝：**

> **把失败/纠错数据直接拼进无条件 BC，收益在噪声级（+0.6pt / −1.67pt / +5pt）。
> 所有取得实质增益的工作，都在数据之外加了一个"区分机制"**——
> 显式条件变量（Parametric Bias）、门控通路（EgoRecovery FiLM gate）、
> 负向引导（AFIL）、样本加权（IWR / Sirius）、或价值函数（offline RL）。

EgoRecovery 那一行值得单独强调：**完全相同的数据，71.2% → 85.0%，差别只在有没有门控通路。**
数据本身不是问题，**把数据丢给一个没有能力区分它的模型**才是问题。

## 6. 回答你的四个问题

### 6.1 该不该加？

**以现在这种形式（独立会话 + 无标签 + 整条 episode + 无条件 ACT）：不该。**
文献预期收益 ≈ 0，而你实测额外引入了一个可被利用的会话捷径（§3.3）和 18× 的条件冲突（§3.1）。

**满足以下四个条件时：应该加，而且值得投入。**

1. **同场次交替采集。** 不要攒批次。每采 N 条成功就采几条纠错，同一个下午、同一个相机、同一批物体摆位分布。
   目标是让"成功 vs 纠错"这个标签**在视觉上不可分**，逼模型去学真正的区分依据（物体相对位姿）。
   这一条单独就能消掉 §3.3。
2. **标签写进数据。** 至少两级：episode 级 `outcome`（成功/失败/纠错），
   帧级 `is_recovery` 区间（操作员按键标注介入起止）。
   现在的 `"Unspecified task"` 让所有有效方法都无法实施。
3. **只保留纠错片段 + 短前导**，而不是整条 1000 帧的 episode。
   §2.2 显示纠错只占失败 episode 的 ~14%（接近段多出的 60 帧 / 941 帧），
   其余 86% 是与成功数据重复但更慢、更窄的名义行为——那部分是纯负担。
4. **纠错要来自策略自己的失败状态。** 你现在的失败数据是人演的（4 次夹爪翻转，
   与成功完全一致，只是接近段慢了 56%）。策略真实的失败模式未必长这样。
   HG-DAgger 式流程：跑当前策略 → 快出错时人接管 → 只记录接管段。

### 6.2 比例怎么设

**先明确一件事：按帧算，不要按 episode 算。**
失败 episode 长 14%，所以 16.55% 的 episode 比例实际是 **18.50% 的帧比例**。
frame-uniform 采样器只认帧。你想要 10% 就得按帧配 10%。

按方案分档：

| 方案 | 纠错帧占比 | 依据 | 预期 |
|---|---|---|---|
| **A. 什么都不改，只调比例** | **≤5%，且只放纠错片段** | CR-DAgger 25% 无效；naive 混合在任何比例都是噪声级 | 无害但也无大益。**只建议作为"确认无害"的对照**，不建议作为方案 |
| **B. 加条件化**（task 字符串区分 / 一维 `is_recovery` 输入 / FiLM 门控） | **20–50% 纠错片段帧** | 2605.07560 用 1:1；AFIL ≈1:1；EgoRecovery 恢复数据占多数 | 这是文献里唯一稳定有正收益的档位 |
| **C. 加权 BC（IWR / Sirius）** | 帧比例可低（5–15%），**权重拉到 3–5×** | IWR/Sirius 的核心就是"数量少、权重高" | 改动最小，不需要改模型结构，只改 sampler |
| **D. 残差策略**（CR-DAgger 路线） | 主策略 0%，残差策略 100% | 完全隔离，主策略不受污染 | 工程量最大，但避开了全部混合问题 |

**建议路线：C → B。**
C 只需要在 LeRobot 的 sampler 上按 episode 标签加权，改动最小，且能直接检验"纠错数据本身有没有信号"；
如果 C 有效再上 B。跳过 A（它只能告诉你"没变坏"）。

**同时必须记住 §4.2(3)：36 条纠错数据对纠错模式的泛化误差是拟合误差的 4.3 倍。**
无论选哪个方案，**纠错数据的绝对条数如果低于 ~100 条，学到的都只是那几条的记忆**。
比例讨论的前提是量够。现在的 72 条大概率还不够。

### 6.3 采集时要注意什么（清单）

按预期收益排序：

1. **不要单独攒失败批次。** 与成功数据同场次、交替采。这是本报告里性价比最高的一条。
2. **锁死相机，并在每次开工前核对头相机画面。**
   §3.3(b) 显示策略对背景像素的依赖强于对物体的依赖，相机被碰一下的代价比想象中大。
   建议：固定一张参考帧，开工前做一次像素级 diff 检查。
3. **把头相机裁到桌面区域**（或在预处理里把桌面以上的背景 mask 掉）。
   这是唯一能**直接消掉 §3.3 全部风险**的改动，而且不需要重新采数据——现有数据重转即可。
   风险是可能损失一部分有用的空间上下文，所以要作为一次对照实验做（§6.4 #3），不要盲改。
4. **背景纳入随机化，或彻底清空。** 现在的背景变量（有人坐着 / 空椅子 / 胶带卷）
   既不受控也不被随机化，正好落在"可被当特征利用"的最坏区间。要么消灭它，要么每条 episode 都换。
5. **纠错场次的物体摆放随机化必须和成功场次一样强。**
   §2.3：失败集左臂关节 std 只有成功集的 47–74%。这直接把"纠错"和"窄工作空间"绑在了一起。
6. **标注 outcome 和介入区间。** 六个数据集现在全是 `"Unspecified task"`。
   哪怕只是把 task 字符串写成 `"...(recovery)"`，也能立刻解锁方案 B/C。
7. **记录 provenance。** 合并时失败 episode 被**前置**到 index 0..71，这件事没有任何记录。
   建议 `conversion_manifest.json` 里保留每条 episode 的源批次与 outcome。
   （合并集甚至没有 `conversion_manifest.json`。）
8. **注意 episode 长度会替你改比例。** 纠错 episode 天然更长（+14%），
   若按 episode 配比，帧比例会系统性超配。
9. **纠错数据要来自策略的真实失败，不是人演的失败。**
   §2.1：你的失败 episode 和成功 episode 的夹爪事件数完全相同，
   人演出来的"失败"是"接近得慢一点"，未必覆盖策略真正会犯的错。
10. **每次训练都要有 rollout 成功率。** 现在磁盘上一个都没有（§0）。
    §4 已经证明训练 loss 和开环 L1 在这个问题上都没有判别力——
    **不测闭环，就没有任何指标能告诉你数据改动是好是坏。**

### 6.4 下一步实验（按性价比排序）

| # | 实验 | 成本 | 能回答什么 |
|---|---|---|---|
| 1 | **给三个已有 checkpoint 补闭环成功率**（各 ≥20 次 rollout，同一初始摆位集合） | 半天 | 全部结论的前提。没有这个，"变差了"仍是主观判断 |
| 2 | **纯成功对照重训**：用 `--dataset.episodes 72..434` 从 `batch_success_361_fail_72` 切出成功子集，250k 步 | 一次训练 | 消掉步数（200k/250k）和视频重编码的差异，得到真正干净的 A/B |
| 3 | **头相机裁剪对照**：把头相机裁到桌面区域重转数据，重训基线 | 一次转换+训练 | 直接检验 §3.3——若裁掉背景后跨场次误差（`batch_1` 的 0.14）明显下降，捷径假说成立 |
| 4 | **加权 BC（方案 C）**：sampler 里把 72 条纠错 episode 权重设 3–5× | 改十几行 | 检验纠错数据本身有没有信号 |
| 5 | **条件化（方案 B）**：纠错 episode 换一个 task 字符串 | 改数据 + 一次训练 | 复现 2605.07560 的 74.2 → 77.8 |
| 6 | **temporal ensembling / 缩短 `n_action_steps`**（100 → 20–30） | 只改推理配置，零训练成本 | 检验 §3.4 的放大效应。**这一条零成本，应该立刻做** |

第 6 条值得特别提：`n_action_steps` 是推理侧参数，改了不用重训。
如果"加失败数据后变差"的表现是"中途卡住 / 走偏 3 秒才回来"，
把它降到 20–30 并开 temporal ensembling，多半能立刻缓解症状——
虽然那只是止血，不解决 §3.1–3.3。

全部在 [`experiment_report/scripts_fail_data/`](./experiment_report/scripts_fail_data/)，需 `conda run -n lerobot`：

| `grip.py` | 每 episode 夹爪翻转次数（§2.1） |
| `conflict.py` | 最近邻条件动作分歧 18×（§3.1–3.2） |
| `revisit.py` | episode 内状态重访（§3.5） |
| `vis.py` / `bg.py` | 平均图与背景带可分性（§3.3a） |
| `locate.py` | 定位合并集里的失败 episode index（§1.1） |
| `eval2.py` | 三 checkpoint 开环 chunk 误差主表（§4.1） |
| `eval3.py` | 失败集 seen/unseen 拆分 + 背景遮挡（§4.2） |
| `eval4.py` | 条带遮挡敏感度（§3.3b） |

### 7.2 局限（请连同结论一起读）

1. **没有闭环数字。** 本文所有"变差"的机制都是推断，不是测量。§6.4 #1 是必须补的。
2. **没有留出成功集。** `batch_success_361 = batch_7 + batch_8`，三次训练都见过全部成功数据。
   §4 成功集那一列是**训练集拟合**，不是泛化。跨场次用 `batch_1` 代替，但它同时含场次偏移，不是干净的留出集。
3. **遮挡消融的绝对倍数是上界。** 涂灰本身把输入推出分布。
   条带之间的**相对比较**是公平的（同尺寸、同退化方式、两个权重上排序一致），
   但"背景依赖强度 = 2.52×"这个数不能直接引用。
4. **"模型用背景做模式选择"是推断而非直接测量。**
   直接证据链是：(a) 两模式在 state 上重叠且动作差 18×；(b) 模型对两者都拟合到 0.012；
   (c) 模型对背景像素的依赖强于对物体；(d) 失败集背景近乎常量且可分。
   要做成实测，需要一个反事实实验：把失败场次的背景换成成功场次的背景（保持手臂与物体不变），
   看预测是否切换模式。这需要分割/合成，本次没做。
5. **基线 200k / 对照 250k**，我用 200k checkpoint 对齐，但基线没有 250k 可比。
6. **`+fail72` 在失败集上没有留出。** §4 里 `+fail72` 那一行的失败集数字全是拟合值。
   `+fail36` 的 0.0516 是本报告唯一一个真正的"纠错模式泛化"测量。
