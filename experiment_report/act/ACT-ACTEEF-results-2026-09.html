摘要

本报告汇总 act（16 维关节动作空间）与 act_eef（14 维末端位姿动作空间）两条策略线在 tidy_up_stationery_le 任务上的全部已完成实验，共涉及 5 份 act_eef 权重、3 份失败数据消融权重、 2 份 act_delta 相对动作权重、11 组架构深度配置，以及 480 次真机试验。

主要发现如下。

  1. 离线开环精度指标与真机成功率在本任务上呈显著负相关。 在 5 个同时具备离线与真机数据的 条件格上，四项准确度型指标（平坦 14 维 MAE、acc@0.25σ、末端位置误差、末端姿态误差）与真机成功率的 Spearman 秩相关一致为 ρ = −0.949，而唯一的平滑度型指标（执行轨迹二阶差分）为 ρ = +0.973 （表 19）。问题不在分辨力，而在符号。
  2. 时序集成系数 temporal_ensemble_coeff 是本轮唯一达到统计显著的可操作变量。 由 0.01 改为 −0.05 使成功率自 80% 降至 50%，三份权重独立复现方向一致， 合并 72/90 vs 45/90，Fisher 精确检验 p = 4.0 × 10⁻⁵（表 16）。离线 MAE 在此对比上给出相反排序。
  3. 数据配方在 act_eef 上不是有效杠杆。 训练集自 363 集增至 616 集，离线 MAE 全跨度仅 7.4%（0.03689–0.03961），其中约 2% 属训练噪声，而五份权重相对空基线的共同领先量为 2.07×–2.23×（表 4）。
  4. 动作表示是有效杠杆。 在 act_delta 线上，相对动作在真留出集上较绝对动作提升 1.83×（0.08417 vs 0.15379 rad），且在每一个 chunk 位置 k 上均更优（表 27、28）。
  5. 两条独立证据链共同指向"增加训练步数买到的是记忆而非泛化"。 act_delta 的后 100k 步留出误差变化 +0.4%（表 27）；act_eef 三条训练曲线一致在 50k–100k 触底后单调变差（表 7）。但真机结果在 act_eef 上与该结论方向相反（200k 优于 100k，3/3 同向，p = 0.168）， 说明"离线留出误差"与"真机成功率"是两个不同的量，可同时成立。
  6. 部署链路改写的量级超过全部架构改动。 K = 40 三次 Hermite 桥单级即造成 +5.1%–+7.8% 的 MAE 代价（表 5）， 而部署栈其余四级合计仅 −0.6%–−1.2%（轻微改善）。在 chunk 模式下 n < 40 时该桥存在硬编码缺陷， 使任意权重均无法前进（§5.4）。

统一建议：以 replan_1 归约下的末端位置误差与 ens_<在用系数> 归约下的二阶差分作为离线主排序键， 弃用平坦 14 维 MAE；保持 temporal_ensemble_coeff = 0.01；部署权重自 acteef_533 换至 616 系。

5.6 chunk 模式在 n < 40 时的硬编码缺陷

send_next_action_chunk（core.py:479-505）：bridge_steps = min(40, chunk.shape[0])； cubic_hermite_segment（trajectory.py:89）：if num_steps == 1: return start.unsqueeze(0)， 其中 start 为机械臂当前实测反馈。

  • chunk = 1：整条下发动作被改写为当前实测位姿，任何 checkpoint 都不会前进。这是缺陷，不是权重弱。
  • chunk = 3/5/10：bridge_steps == chunk 长度，整条 chunk 全为桥，原始策略帧一帧不剩， 且 start_velocity = 0.0 使每次下发自零速重启（走停现象）。另外，桥只改写 12 个位姿维 （ACTION_LAYOUT 的 n_bridge），两个夹爪维保持原始时序，导致抓取时序与手臂运动脱钩。

ENABLE_FIXED_K_REAL_STATE_BRIDGE = True（core.py:55），默认开启。 使用者在 chunk 模式下扫描到的成功率曲线，度量的是这座桥，不是权重之间的差别。

10. 效度威胁与未测项

10.1 效度威胁（按严重度）

  1. 真机实验协议完全未知（最大单一威胁）。任务定义、成功判据、每次试验的初始摆放随机化方式、 16 格的测试顺序、操作者是否盲测——全部未记录。若 16 格按表格顺序连续跑， 则"权重"与"时间/场地漂移/操作者熟练度"完全共线，§5.1 中 533 = 60% 存在无法排除的替代解释。 澄清成本为零（一句话），但它决定该条结论是否成立。
  2. 平滑度不是被证实的预测器。ρ = +0.973 建立在 5 个点、2 个自由度上， 且其在跨权重段的离线跨度仅 6.7%（0.000210 vs 0.000224），需先证明 6.7% 的离线跨度 对应得上 20 点的真机跨度。未证明。
  3. ens_* 与成功率之间仍无任何被验证的离线预测器。本轮做的是排除（四项准确度指标出局）， 剩下一个候选，不是结论。
  4. N_eff 机制未分离（§5.2）：三个共变量，两个数据点。
  5. acteef_505 无 TE 模式离线数字，§5.5 的倒挂比较基于已知量错对象的 chunk 链。
  6. 533 vs 其余三份的 p = 0.049 依赖是否将 acteef_505 并入。505 是不同训练集， 合并它是一个假设而非事实；仅用两份孪生时 p = 0.075。
  7. 616_eef_actionsame 的污染指纹从未独立核对——其数据集不在本机， 去污染使用 batch_success_616_eef 作替身（两份 checkpoint 归一化统计量逐位相同）。
  8. act_delta 与失败数据两条线均为单数据集、单任务结论，未做跨任务复现。
  9. 训练侧与部署侧存在三份不同步的 lerobot 代码副本，且 job.json 无任何代码版本字段。 act_delta 第二轮的 use_relative_actions 开关是在 site-packages 手工编辑的 dataclass 默认值， 重跑同一 sbatch 会静默退回绝对动作。任何"改了 X 之后效果变了"的结论在此前提下都不可信。

10.2 明确未测（不得当作已测）

11. 建议

按"证据支撑 × 实施成本"排序。

11.1 立即可做（零训练成本）

  1. 保持 temporal_ensemble_coeff = 0.01。 唯一达到统计显著的结论（p = 4.0e-5）。 下一个应测的是 coeff = 0：其在三份权重、每一个离线指标（含唯一未被证伪的平滑度）上 均优于 0.01（表 12），N_eff 为最大值 100，滞后 1.65 s 反而更小。 两把尺子同向、离线已算好、改一行 YAML、30 次试验。
  2. coeff = +0.05 作为判别实验。 其 N_eff 与 −0.05 相同（39.5），仅滞后与视野方向相反： 若也降至约 50% → 机制是平均次数，coeff = 0 即最优点，实验到此为止； 若仍在 80% 附近 → 机制是视野方向，值得继续往正方向扫。一份权重 30 次即可。
  3. 补 acteef_533 @ −0.05 一格（30 次）。 用以判定 −30 点是否为与权重无关的固定代价。 若可加，则系数效应与权重效应可独立引用；若存在交互，表 16 的 p = 0.049 需重算。
  4. 补记真机协议一句话：测试顺序、成功判据、初始摆放是否随机化、是否盲测。 零成本，但它决定 §5.1 结论是否站得住。
  5. 修 bridge_steps，或下线 chunk 模式。 min(40, chunk.shape[0]) 应在 chunk 短于 K 时不建桥， 而非把整条 chunk 变成桥。若 TE 即是答案，该路径可直接下线。
  6. 修正 MASTER-LEDGER §0 第 1 条：真机口径上 acteef_533 已有三个反例。

11.2 部署配置

  1. 将 deploy_config_eef.yaml 自 acteef_533 换出。 三份 80% 权重中优先 acteef_616as： 它在唯一未被证伪的指标（TE 二阶差分 0.000210）上是三份中最好的，且有孪生 acteef_616 可随时复核。 acteef_505 同为 80% 但无 TE 模式离线数字，换它等于放弃离线交叉验证。 换出的理由是末端位置 mm 与右夹爪 MAE，不是平坦 MAE。
  2. act_delta 线保留 n_action_steps = 50（免费、无副作用、方向正确），但不应对其抱有期待。

11.3 评测方法论

  1. 离线主表改为三栏：replan_1 的末端位置 mm（无滞后能力代理，本轮押中）； ens_<在用系数> 的二阶差分（唯一未被证伪，ρ = +0.973）； plan consistency（架构级筛子，同架构选权重时不用）。 删除平坦 14 维 MAE 作为主排序键——两份报告给出两条独立理由（表 19 的 ρ = −0.949； 表 14 的尺度与信息量双重失衡）。
  2. 今后每个 job 都保存中间步 checkpoint。 save_freq 自 50000 调至 10000 的存储代价， 远小于"想比较时发现 checkpoint 不存在"（533_eef / 361_eef 已因此永久失去训练曲线）。
  3. 不要为 200k vs 100k 追加试验。 10 点差、3/3 同向已足够决策（用 200k）； 做成 p < 0.05 需每格约 300 次。用方向，不买 p 值。
  4. 训练侧改为 editable 安装指向 lerobot_vlahost，或在 job.json 记录 git commit。 不做这一步，后续所有"改了 X 效果变了"的结论都不可信。
  5. 在 save_checkpoint 写入 arch_version 字段并在部署脚本校验， 以规避 [0]/[-1] 这类静默的 checkpoint 破坏性变更。

11.4 训练侧

  1. 停止把"加数据量"当作 act_eef 的杠杆（363 → 616 集仅换来 7.4% 离线跨度，其中约 2% 是噪声）。 数据配方（哪些 episode）比数据量更像变量，但即使是配方本轮也未量出可靠的方向性收益。
  2. 失败/纠错数据在当前形式下不应加入。 不是因为失败数据有毒，而是它同时携带三样无关负载： 独立采集会话块（视觉捷径）、同状态 18× 动作分歧、系统性更长的 episode。 若要加：要么降至 ≤ 5% 帧且只保留纠错片段，要么加条件化后拉至 20%–50% 并按 IWR 加权； 中间地带无价值。采集时不要单独攒一个失败批次（须与成功数据同场次交替采集）， 把标签写进数据（当前六个数据集 task 全为 "Unspecified task"）， 失败数据须来自策略自身的失败而非人工演示的失败。
  3. act_delta 若继续，先用 batch7（163 条）重训并切出验证集，用留出 MAE 选 checkpoint 而非 last。
  4. dec_layers ∈ {1, 4, 7} 消融应尽快补上。在拿到该组数据前，dec_layers = 1 是风险更低的默认值 （同时匹配上游 ACT 与 LeRobot）。若要加深，先补相机身份嵌入再谈加深 encoder—— 当前每路相机的 2D 正弦位置编码都从原点重新开始，模型须先从内容与拼接顺序中"猜"出视角身份。
  5. 拆分 enc_layers 为 n_encoder_layers / n_vae_encoder_layers： CVAE style encoder 在推理时完全不运行，与 obs encoder 绑定调参是纯浪费（训练侧每层 13.3 ms / 0.93 GB）。
