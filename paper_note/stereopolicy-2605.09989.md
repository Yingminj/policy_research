## 一句话总结

针对「单目缺深度、而显式 3D（深度图/点云）在真实世界又噪声大、易被材质击穿、且缺成熟预训练主干」这一双向夹击，本文主张**跳过一切显式 3D 重建**：左右两张同步图各过一个共享权重的 2D 预训练编码器，再用一个 2 层的 cross-attention「Stereo Transformer」（带 2D RoPE）隐式学左右对应，输出的融合特征直接当作 diffusion policy 或 VLA 的观测条件；仿真 14 组设置平均 82.0%（RGB 65.7%、RGBD-3DDA 76.4%、DP3 53.4%，本人按 Table 2 逐格计算），真机 5 项桌面任务平均 59.0%（RGB 42.0%、RGB-D 41.0%、PointNet 14.0%），推理只比单目 RGB 慢 1.12×。

## 研究背景与动机

### 领域现状

「怎么给操作策略补上 3D」目前有四条成型路线：(1) 单目 RGB + 预训练 2D 主干（DP、π0、RT 系），靠数据堆出 2D→3D 的抬升；(2) 显式深度/点云编码（DP3、PointNet、3D Diffuser Actor）；(3) 多视角投影图 + 已知外参（RVT-2、BridgeVLA，以及本目录 `mv-vdp-2604.03181.md` 那条线）；(4) 把 2D 预训练表征 lift 进 3D 场（NeRF 类）。与此同时计算机视觉侧的双目匹配（FoundationStereo、Stereo Anywhere 等）已经做到强零样本泛化。

### 现有痛点

作者把显式 3D 的代价拆成三条，写得相当具体：

1. **显式 3D 对传感器噪声、标定误差与物体材质敏感**。深度图丢精细语义，点云在反光/透明物体上直接「物体消失」（Fig. 7 展示玻璃杯在深度视频与重建点云中整块缺失）。
2. **3D 预训练编码器远不如 2D 成熟**，根因是大规模 3D 数据与可扩展 3D 主干都还稀缺。
3. **显式视差估计管线有实质推理开销**，与操作任务要求的低延迟冲突。

而已有的「机器人里的双目」工作（SimNet 类、ClearDepth 等）几乎都是先估显式深度/占据，再接控制模块——等于把双目当成一个深度传感器用，仍然吃前两条代价。

### 核心矛盾

> **深度信息只在 3D 空间里可得，而可用的大规模预训练知识只在 2D 图像空间里可得；把双目转成深度就退回了脆弱的显式 3D，不转就用不上视差。**

### 本文目标

在不引入任何显式 3D 表示、不做视差监督、不换 2D 主干生态的前提下，让策略吃到视差；并给出可操作的硬件配置准则（基线长度、相机角度）与编码器设计准则。成功标准落在三处：全面超过 RGB / RGB-D / 点云 / 多视角四类基线；能插进已预训练的单目 VLA 并带来增益；延迟不显著恶化。

### 切入角度

**表征驱动 + 架构驱动的最小组合**：不改数据形态（双目图本来就是 2D 编码器的原生输入），只在编码器后面插一个轻量融合模块。

### 核心 idea

关键观察是：**下游需要的从来不是像素级视差图，而是「任务相关的几何嵌入」**；既然如此，就不必让网络先解一个比控制更难的稠密对应问题。于是把视差学习降级成一个 cross-attention：左图的 query 去右图找 key，2D RoPE 保住空间位置，注意力自己会沿极线找对应。整条链路上没有任何一处需要相机内外参、深度标定或视差真值。

## 方法详解

### 整体框架（Fig. 2）

```
N 对同步双目图 (I^L_{t,i}, I^R_{t,i})，i = 1..N 个视角
   ├─ 共享权重 2D 编码器 V_i(·)：ResNet18 + FPN（多尺度）
   ├─ 【仅外部视角】拼接冻结 DINOv2 特征
   │     4×4 stride-4 卷积降采样 DINOv2 → 与 CNN 特征 concat → MLP 投影
   │     （CNN 因此被训练成「适配 ViT 特征」的角色）
   ↓
   Stereo Transformer_i（每视角一个，2 层 × 8 头）
   ├─ self-attention：像素之间
   ├─ cross-attention：左图 ↔ 右图，**2D RoPE 只加在 q/k 投影上**
   └─ MLP block
   ↓  MLP → 每视角压成 z_{t,i} ∈ R^128
   ↓
z_obs = [z_{t,1} ‖ z_{t,2} ‖ … ‖ z_{t,N} ‖ s_t]   （s_t = 本体感觉）
   ↓
   ├─ StereoPolicy-DP：作为 UNet 去噪网络的 condition，ε̂ = ε_θ(x^(τ), τ, z_obs)
   └─ StereoPolicy-VLA：**替换掉** VLA 原有的单目视觉 embedding，端到端微调
```

### 关键设计

**① 隐式对应而非显式视差（§2.1）**
解决的是「显式视差管线又慢又脆」。做法是让 cross-attention 承担对应搜索，用 2D RoPE 提供位置先验以「鼓励显式的跨视角对应学习」。隐含假设：**任务所需的几何信息远少于稠密视差图所携带的信息**——只要够判断「夹爪离目标还差多少」即可。代价是没有任何可解释的几何量输出，也无法用现成的视差数据集去预训练这个模块。

**② 左右编码器共享权重（§2.1）**
论文的理由是「保持几何一致性」。这是个便宜且正确的选择：不共享的话左右特征空间会漂移，cross-attention 需要额外学一个对齐。

**③ DINOv2 只加在外部视角（§2.1，Eq. 1）**
解决的是「弱纹理/遮挡区域极线对应不可靠」，用单目语义先验去消歧。**但作者实测 DINOv2 在腕部视角上是负收益**，归因于与第一人称影像的域失配，于是只对外部视角启用。这是全文最值得记住的一条经验，也是被写进方法（而非只写进消融）的少数几条之一。

**④ 逐视角独立融合，再压成单个 128 维向量（§2.1，Eq. 2–3）**
Stereo fusion 对每个相机独立跑，注意力只在一对左右图之间，**复杂度对相机数是线性的**。但代价极大：附录 B.1 明说「Stereo features from each view are then projected to a 128-dimensional latent space using an MLP **to ensure a consistent token dimension for fair comparison**」——即每个视角最终只剩一个 128 维向量。这既丢掉了跨视角的全局几何，也把刚刚算出来的稠密对应重新压回了全局特征（见「与既有报告的交叉」C 节）。

**⑤ VLA 侧是「替换」而非「增补」（§2.3）**
StereoPolicy-VLA 用融合后的立体表征**取代**原有单目视觉 embedding，然后端到端微调。这是个激进选择：预训练 VLM 的视觉接口被换掉，语义表征靠微调重新对齐。作者用「without disrupting their learned semantic representations」来辩护，但没有给出任何证据（例如语义/语言 grounding 任务上的保持度）。

| 项 | 设置 |

### 消融与分析

**Q3 — 基线/距离比 r（Fig. 9）**：扫 baseline ∈ {2, 6, 10} cm × 距离 ∈ [0.59, 0.99] m，结论是性能由**比值**而非任一单项决定，最优区间 **r = baseline / distance ∈ [0.09, 0.13]**；桌面典型 0.6–0.8 m 对应 6 cm 基线最佳。r 太小视差不足，r 太大重叠区不够、几何不一致。

**Q3 — 相机角度（Fig. 8b）**：ToolHang 上扫 10 个机位，增益最大在正面视角（frontview **+18%**、frontview-high **+14%**），侧视增益最小（重叠少、自遮挡强）。结论：**单目几何最模糊的地方，正是双目增益最大的地方。**

**Q4 — 主干与组件（Fig. 10，ToolHang / 100 条）**：
- 低数据（<100 条）下 **OpenCLIP-B/16、SigLIP-SO400M/14 明显优于 ResNet18**；
- **多尺度特征很关键**：EdgeNeXt-S 或 ResNet18+FPN 都显著帮助 Stereo Transformer；
- 冻结 DINOv2 拼接：外部视角有增益，**腕部视角有损**；
- **去掉 Stereo Transformer：0.94 → 0.85**。

### 关键发现

- **真正的对手是 3DDA，不是 RGB。** 仿真平均 82.0 vs 76.4，只差 5.6 pt，而 3DDA 用的是仿真里的**完美深度**。真机上 3DDA 领先 RGB 仅 3 pt（45 vs 42）——说明「完美深度」这个优势在真机上被噪声吃干净了。这条比论文主推的 vs RGB 对比信息量大得多。
- **点云路线在两个环境下同时被证伪。** 仿真里 DP3 垫底（53.4），真机里 PointNet 14%。作者直接反驳了 DP3 原文的「点云更 sample-efficient」主张：「here we observe the opposite」，并强调点云「heavily rely on careful pre-processing；没有仔细裁剪与采样，性能会轻易掉到 0」。
- **增益集中在低数据与几何模糊场景。** 高数据格（Transport、Square 200 条）几乎打平；正视图 +18%、侧视图接近 0。这界定了适用范围：**双目买的是数据效率与几何消歧，不是天花板。**
- **透明/反光是「改善」而非「解决」。** 玻璃杯 3/20，作者在 Limitations 里主动承认「overall success rate is still relatively low」。
- **可以拆掉腕部相机。** Stereo 只掉 2 pt，DP3 掉 14 pt。作者点出实际价值：腕部相机会与物体碰撞。这是个被低估的工程收益。

## 亮点与洞察

- **「下游要的是任务相关的几何嵌入，不是像素级视差」这个降级判断本身就是贡献。** 附录 A 说得很清楚：现代双目匹配方法优化的是逐像素视差，与下游任务无关，还需要额外模块产出控制信号。把一个比控制更难的中间问题（稠密对应）从管线里删掉，是可以直接迁移到别处的方法论。
- **r ≈ 0.10 这条硬件准则是全文最可复用的产出。** 它把「双目怎么配」从玄学变成一个可计算的量，且给了明确失效机理（r 小 → 视差不足；r 大 → 重叠不足）。任何要上双目的项目都可以直接用。
- **「分视角决定用不用 DINOv2」是个反直觉但有价值的经验。** 通常做法是全局统一编码器配置；本文说明**编码器配置应该按视角的域分布来选**，因为腕部第一人称影像在互联网预训练分布之外。
- **逐视角独立融合让复杂度对相机数保持线性。** 相比 MV-VDP 那种沿视角维拼接（token 数 × V）再跑 view-attention 的做法，这是一个便宜得多的工程折中。
- **1.12× 的延迟开销是个有说服力的数字**，因为它落在迭代去噪的阴影里。这提示了一个通用模式：只要主干是迭代式的，感知侧的架构增强几乎是免费的。

## 局限与展望

### 作者承认的局限

- 只覆盖较小规模的桌面与移动操作，未验证更大场景。
- 透明/反光物体虽有改善，**绝对成功率仍然很低**。
- 性能对**光照、反光、双目相机摆位**敏感。
- 未来方向：扩到带双目对的大规模数据集（点名 DROID），扩到更多本体。

### 读者应警惕的局限（我的判断）

1. **最关键的基线缺失：「现代双目匹配器 → 深度 → 策略」这一组没有做。** 论文的核心主张是「隐式 ≥ 显式」，但它的显式对照是 **RGB-D 深度图与由 RGB-D 重建的点云**。而作者自己的参考文献里就有 FoundationStereo [76] 与 Stereo Anywhere [2] 这类强零样本双目匹配模型。没有这一组，就无法区分两种解释：(a) 双目光子里的信息本来就更多；(b) 隐式融合优于显式重建。**只有 (b) 才是论文声称的贡献，而恰恰是 (b) 没被测。**
2. **真机 RGB-D 基线的深度来源全文未交代。** C.1 只说用了两台 ZED Mini——而 ZED 的深度本身就是双目算出来的。若真机 RGB-D 用的就是 ZED 内置深度，那 Table 1 其实是一个非常漂亮的「同一批光子，隐式 59% vs 显式 41%」对照，论文却没有说；若来自别的传感器，则整张表存在传感器混淆。**这是一句话就能澄清、却没写的事。**
3. **Multi-View 基线很可能被削弱了，导致融合模块的贡献被夸大。** 正文用「StereoPolicy-DP outperforms multi-view-based policies …validating the effectiveness of our stereo architecture」来论证 Stereo Transformer 的价值，ToolHang 100 条上是 **54 vs 94（+40 pt）**。但内部消融「去掉 Stereo Transformer」只掉到 **85（−9 pt）**。两个数差了 4 倍多，唯一合理的解释是 Multi-View 基线没有共享 FPN + DINOv2 这套编码器（B.1 只对 RGB / RGB-D 明说用 ResNet18，Multi-View 那段没说）。**融合模块的真实贡献应以 94 → 85 为准，而不是 94 → 54。**
4. **仿真数字是 max-over-checkpoints。** B.4 明写「报告训练全程的最高成功率」。Robomimic 每 50 epoch 存一次共 10 个点，取最大值系统性上偏，且**偏向方差更大的方法**。3 seed 的标准差（很多是 0.0 / 1.6）是这个「最大值统计量」的标准差，不是性能的标准差，不能当作置信区间读。
5. **附录 D.1 的硬件数字自相矛盾。** 原文写「baseline distance …set to **66 cm** for external cameras and **22 cm** for the wrist camera」。ZED Mini 的物理基线是固定的 63 mm，且论文自己 §3.3 的最优区间是 6 cm @ 0.6–0.8 m。66 cm / 22 cm 几乎肯定是 **6.6 cm / 2.2 cm 的小数点错误**。顺带说明：真机设置本来就落在最优区间内，因此**真机结果并不构成对 r 准则的检验**。
6. **VLA 部分正文措辞与项目页数字冲突**（见上文表格三点）。且 VLA 数字不在论文里，只在项目页——这是引用风险最高的一块。
7. **「拆掉腕部相机不掉性能」的说服力有限。** Stereo −2 pt、RGB −4 pt，在 50 次 rollout 下分别是 1 次与 2 次成功之差，且又是 max 统计量。唯一量级可信的是 DP3 的 −14。正文「RGB and RGB-D policies' performance **immediately drop**」是过度解读。
8. **真机全部无 seed、无重复、无置信区间。** 每格 20 次试验，59% vs 45% 相当于 59/100 vs 45/100（5 任务合计），趋势可信，但单任务级别的比较（如 Steel Cup 13 vs 10）落在噪声里。
9. **新颖性是增量的，而且作者自己写明了。** 附录 A：「While [65] and [38] also use stereo inputs for end-to-end dexterous grasping, they do not study stereo feature fusion or compare against explicit 3D baselines」——即前人已经做过端到端双目策略，本文的增量是**系统性研究 + 融合模块 + 硬件准则**，不是「首次」。
10. **不可复现**：无代码、无 checkpoint，真机需两台 ZED Mini + Franka + Galaxea R1 Pro，VLA 微调需 8× H100 跑 60–80K step。
11. **Fig. 5 / Fig. 6 引用错位**（RoboCasa 那段写「As summarized in Figure 6」，实际应为 Figure 5），小瑕疵但说明 v2 校对不严。

### 可做的下一步

1. **补那个缺失的基线**：FoundationStereo → 深度/点云 → 同一个 DP。这是唯一能把「隐式 vs 显式」这个主张钉死的实验，成本很低。
2. **把 128 维瓶颈拆掉**（见交叉 C 节）：Stereo Transformer 的输出保留 patch 级 token，用 Patch Policy 的 block-causal mask 喂进策略。作者自己承认这个投影是「for fair comparison」而非性能最优——这意味着本文的所有数字很可能是下界。
3. **跨视角注意力**：目前视角之间完全不交互。加一层轻量 view-attention（MV-VDP 的做法）应能在多相机设置下再拿一段。
4. **用双目自监督预训练 Stereo Transformer**：现在它完全从 100–300 条示教里从头学极线对应，这是全文最不合理的一环。用 DROID 或任意双目视频做一次视差自监督预训练几乎必然有效，且作者已经点名 DROID。
5. **验证 VLA 侧的语义保持度**：既然是「替换」视觉 embedding，就该测一下语言 grounding 有没有退化。

- **vs 机器人里的双目前作 [65][38]**：作者承认存在，差异是「未研究融合、未与显式 3D 基线对比」。

## 与既有报告的交叉

### A. 与 `mv-vdp-2604.03181.md`：同一个问题的两个极端解

两篇打的是**完全相同的靶子**——「动作发生在 3D，而预训练知识锁在 2D」——但给出了坐标轴两端的答案：

| | MV-VDP | StereoPolicy |
|---|---|---|
| 对 3D 的处理 | 先建显式点云，再**渲染回** 2D | **根本不建** |
| 几何如何进入网络 | 解析可逆的投影 / 反投影（Appendix B） | 注意力自己学，无解析形式 |
| 几何显式度 | 高 | 低 |
| 与基座原生格式的 gap | 需要渲染这一步来消除 | **天然为 0** |
| 硬件门槛 | 标定好的多台深度相机 | 一对未标定的双目 |
| 精度天花板 | 热力图量化 ≈4 mm/px | 视差分辨率，无显式量化 |
| 独有红利 | 投影前做 SE(3) 数据增广；预测视频可当安全闸门 | 无 |

**两条独立路线得到的同一个结论，值得当作领域共识来引用**：显式点云编码器（DP3 / PointNet）在真机上是失败的。MV-VDP 真机 DP3 **0/70**，StereoPolicy 真机 PointNet **14%**、DP3 **27%**，两篇给出的病因也一致（点云对传感器噪声与材质极度敏感 + 缺大规模预训练）。这比任何单篇的证据都硬。

**分歧点是「深度信息该在哪一层被消费」。** 用 MV-VDP 自己的方法论（「让数据适配基座的原生格式，而不是给基座接 adapter」）去看 StereoPolicy，会发现后者是这条论证的极限情形——双目图**本来就已经**是 2D 编码器的原生输入，连渲染都省了。代价也随之明确：**格式对齐度 ↑，几何显式度 ↓**。StereoPolicy 拿不到跨视角的全局 3D 结构（它的视角之间完全不交互），只拿到极线方向上的局部视差；也拿不到 MV-VDP 那些依赖显式 3D 的红利（投影前的 SE(3) 增广、视频预检当安全闸门、虚拟相机带来的跨工位不变性）。

**一条必须小心的引用陷阱**：两篇都自称 data-efficient，但不在一个量级。MV-VDP 是**每任务 5–10 条**示教，StereoPolicy 真机是**每任务 200 条**示教且平均只到 59%。别把两个「数据高效」并列写进同一句话。

### B. 与 `../vision-backbone-why-resnet18-2026-08.md`：三处可更新，一处需修正

该报告已在 §4 表格、§5 决策表、参考文献三处引用本文 v1 并标注「未逐条核对」。核对结果：

**B-1（可去掉「未核对」标记）** §5 决策表那行「外部视角 + 腕部视角混合 → 外部用冻结 DINOv2、腕部保留可训 ResNet18」——**v2 正文 §2.1 与 Q4 两处都明确写了**，原话是「improves external views but degrades wrist-view performance, likely due to domain mismatch with egocentric imagery」，而且这个结论被写进了方法本身（DINOv2 只对外部视角启用），不只是消融。这同时是报告 §3.8「腕部相机在 ViT 预训练分布之外」的**独立第三方实证**，也与 `vista-2606.04708.md` 的「鱼眼腕视对预训练 VLM 属于 OOD」构成同一族证据。**注意：论文只给了定性描述，没有逐视角数字。**

**B-2（需要修正读法）** 报告 §4 表格里那行「StereoPolicy：低数据下 OpenCLIP-B/16、SigLIP-SO400M/14 **反而**优于 ResNet18」——原文确实这么说（Q4），但有三个此前不知道的限定条件，**合起来足以改变结论的方向**：

1. 证据只是**一张图**（Fig. 10）、**一个任务**（ToolHang）、**一个数据点**（100 条），**没有数值表**；
2. **论文自己的主实验用的是 ResNet18 + FPN，不是 SigLIP**——作者声称大主干在低数据更好，却没有用它跑任何一个主结果。这个内部矛盾比那张图本身更有信息量；
3. 关键区别在于**这些大主干在这里是当特征提取器用的**（DINOv2 明确冻结），而 DP Table 5 那个 0.22 是 **ViT 从头端到端训**。

因此**这条不构成对报告 §0 结论的反证，反而是补强**。报告 §0 的准确表述是「劣势不在 ViT 架构本身，而在『ViT × 从头训练 × 一百条演示』这个组合」——StereoPolicy 的 Q4 恰好落在另一格（**冻结/预训练 ViT 特征 × 一百条演示**），而那一格本来就是 DP Table 5 里 ViT 微调拿 0.98 的那一格。建议把 §4 那行改写为：「低数据下，**作为冻结特征提取器**的大主干优于 ResNet18；但该文主实验仍用 ResNet18+FPN，未自洽。」

**B-3（新增一条可抄的结构选择）** 报告 §3.4 担心的「多相机 × 高分辨率下 O(N²) 爆炸」，StereoPolicy 给了一个现成的规避方式：**融合逐视角独立进行，注意力只在一对左右图之间跑，因此复杂度对相机数是线性的**。对 3 相机 × 480×640 的配置，这比「所有相机 token 拼起来跑全局注意力」便宜一个数量级。代价是跨视角几何完全不建模——如果任务需要跨相机三角化，这条不适用。

**B-4（一个已被绕过的 bug）** 报告 §6 第 1 条指出的「三路相机位置编码逐字节相同、模型分不清 token 来自哪个相机」——StereoPolicy 的结构天然没有这个问题：每个视角有**独立的** `StereoTrans_i`，输出分别投影后再拼接，视角身份编码在参数里而非位置编码里。这是比补 `nn.Embedding(n_cams, hidden_dim)` 更彻底的做法，代价是参数量随相机数线性增长。**那个 2 小时的修复仍然应该先做**（它是免费的），但如果之后要重构视觉前端，逐视角独立编码器是值得考虑的形态。

### C. 与 `patch-policy-2607.18236.md`：本文的数字很可能是下界

这是我认为**最有行动价值**的一条交叉。

Patch Policy 的核心结论是「全局池化是一道陡崖，不是一个旋钮」（压缩阶梯 256/64/16/4/1）。而 StereoPolicy 在 Stereo Transformer 里辛苦算完稠密的左右对应之后，**把每个视角压成了单个 128 维向量**——附录 B.1 原文：「projected to a 128-dimensional latent space using an MLP **to ensure a consistent token dimension for fair comparison**」。

也就是说：**它为了公平对比，主动把自己压回了 Patch Policy 判定为陡崖底部的那一格。** 按 Patch Policy Table 4 的斜率，这里损失的量级不小，而它仍然拿到了 ToolHang 100 条 53 → 94 的提升。合理推论是：**本文报告的所有数字都是下界**，Stereo Transformer 的真实上限还没被测到。

**这直接给出一个成本很低、且没人做过的后续课题**：`Stereo Transformer 的 patch 级输出 + Patch Policy 的 block-causal mask`。两边的组件都是现成的，两篇论文都没往这个方向走一步，而且动机完全互补——一个在解决「几何从哪来」，一个在解决「稠密特征怎么进策略」。

⚠️ 但要先处理一件事：Patch Policy 自己承认的最大局限是 `O((T·P)²)` **在多相机下未验证**。StereoPolicy 的逐视角线性结构恰好是这个问题的解法之一。所以组合的正确形态是「每视角独立跑 Stereo Transformer 出 patch token → 跨视角 + 跨时间用 block-causal mask」，而不是把所有 token 一股脑拼起来。

### D. 与 `simfoundry-2606.28276.md`：那个缺失的基线，材料已经齐了

SimFoundry 笔记记录了它的深度来源是「DepthAnything3（单目/视频）或 **FoundationStereo（双目）**」（流水线阶段 2）。而 StereoPolicy 最致命的缺口正是「现代双目匹配器 → 深度 → 策略」这一组对照（局限 1）。

**这个实验的两端都已经在手**：FoundationStereo 的用法（SimFoundry 笔记 §9 有仓库级实现难度评估），以及 StereoPolicy 的完整架构描述。这个对照能回答一个本文没能回答、但对整个「隐式 vs 显式」争论是决定性的问题：**双目的收益究竟来自「更多的光子」还是「不做重建」？** 如果 FoundationStereo → DP 就能接近 StereoPolicy-DP，那本文的贡献退化成「省掉了重建的延迟」；如果差距仍然很大，「隐式融合」才真正成立。

顺带一条方法论上的重复出现：SimFoundry 笔记批评过它「N=3~5 算 Pearson、25 rollout、无 CI」；StereoPolicy 是「50 rollout 取训练全程最大值、3 seed、真机 20 次无重复」。**同一类评测松弛在最近读的每一篇里都出现了**——这本身就是可以写进 `../real-world-policy-evaluation-2026-08.md` 那条线的观察：操作策略领域当前的评测口径普遍不足以支撑论文里的强比较句。

### E. 与 `vista-2606.04708.md`：腕部相机是一个稳定的失配点

VISTA 把 UMI 数据的病因之一诊断为「感知失配——腕装约 180° 鱼眼对预训练 VLM 属于 OOD」，解法是用 8M 规模的同域 UMI-VQA 共训。StereoPolicy 在完全不同的硬件（ZED Mini，非鱼眼）上独立观测到同一现象：**冻结 DINOv2 在腕部视角上是负收益**。

两篇加起来说明：**「腕部相机 × 互联网预训练视觉主干」是一个稳定的、跨硬件的域失配点，不是某个数据集的偶然。** 处理方式有三档，成本递增：

1. **StereoPolicy 式**：分视角关掉预训练特征，腕部只用可训 CNN（零成本，`vision-backbone` §5 决策表已采纳）；
2. **X-Distill 式**：把 ViT 先验蒸馏进可训小骨架（中等成本，该报告 §6 已列为优先级 3 的首选）；
3. **VISTA 式**：造同域 VQA 数据把 backbone 的 grounding 拉到腕部域（高成本，需 8M 量级数据）。

## 评分

- **新颖性 2.5 / 5** — 作者自己在附录 A 承认前人已做过端到端双目策略；Stereo Transformer 是标准的 self / cross 交替 + 2D RoPE，在双目匹配文献里是常规配置。真正新的是「把它系统地放进操作策略并与显式 3D 全面对比」这件事，以及 r ≈ 0.10 这条准则。属于扎实的实证工作，不是方法创新。
- **实验充分度 3 / 5** — 广度好（3 个仿真 benchmark + 7 个真机任务 + 2 个 VLA + 2 种本体 + 6 类基线 + 硬件扫描 + 主干横评）。扣分很重：缺最关键的双目匹配器基线；Multi-View 基线疑似被削弱导致融合模块贡献被夸大约 4 倍；仿真用 max-over-checkpoints；VLA 数字不在论文里且与正文措辞冲突；真机无重复无 CI。
- **写作质量 3 / 5** — 动机段（三条显式 3D 的代价）写得很清楚，失效案例分析（附录 F）有价值，且**主动承认 Transport 这类任务单目已足够**，这份坦诚少见。瑕疵密集：D.1 的 66 cm / 22 cm 小数点错误、Fig. 5/6 引用错位、VLA「modest」与 +22.8 pt 的矛盾、Table 4 表头列错位。
- **复现与落地价值 3.5 / 5** — 方法本身极易复现（一个 2 层 transformer 插在编码器后面），硬件门槛低（一对双目，**不需要标定**）、延迟只 +12%、可以省掉腕部相机。但无代码、无 checkpoint，VLA 部分需 8× H100。**思路的落地价值高，论文本身的可复现性低。**
- **对当前研究的启发 4 / 5** — 不是因为方法，而是因为它和已有的四篇笔记形成了一张能读的图：3D 先验的消费方式（vs MV-VDP）、主干选择的边界条件（vs `vision-backbone` 报告）、稠密性瓶颈（vs Patch Policy）、腕部域失配（vs VISTA）。单独看是一篇中等偏上的实证论文；放进这张图里，它把好几条线的分歧点标定清楚了。

## 实践 takeaway

**可以直接借的**

1. **r = baseline / distance ∈ [0.09, 0.13]**。要上双目就照这个配，桌面 0.6–0.8 m 用 6 cm 基线。这是全文最硬的可迁移产出。
2. **按视角选编码器配置，而不是全局统一**：外部视角上冻结的大主干特征（DINOv2 / SigLIP）有收益，腕部视角上有害。
3. **逐视角独立融合 → 复杂度对相机数线性**。3 相机配置下值得抄的结构选择。
4. **感知侧增强在迭代式主干下几乎免费**（1.12×，因为落在去噪的阴影里）。这个模式对 diffusion / flow matching 策略普遍成立。
5. **双目可以让你拆掉腕部相机**（−2 pt vs 点云的 −14 pt）。腕部相机会撞物体，这是实打实的工程收益。

**要小心的**

1. **别把「隐式 > 显式」当结论引用**——那个决定性的基线（现代双目匹配器 → 深度 → 策略）没做。目前能安全说的只是「隐式 > **RGB-D 传感器深度及其重建的点云**」。
2. **别引用 vs Multi-View 的 +40 pt**（54 → 94）来说明融合模块的价值，用内部消融的 **94 → 85**。
3. **VLA 的数字（尤其 30 条下的 +22.8 pt）只存在于项目页**，且与正文「modest」的措辞冲突、且非单调。引用前务必标注来源，或干脆不引。
4. **仿真数字是训练全程最大值**，3 seed 的 std 不是置信区间。
5. **附录 D.1 的 66 cm / 22 cm 是笔误**（应为 6.6 / 2.2 cm），别照抄进自己的相关工作。
6. **两个「data-efficient」不是一个量级**：MV-VDP 每任务 5–10 条，本文真机每任务 200 条。

**它打开的问题**

> 本文和 MV-VDP 各自证明了「不用显式 3D 编码器也能拿到 3D 能力」，但一个把几何固化进渲染管线（解析、可逆、有量化上限），一个把几何完全交给注意力（无上限、无解释、无先验）。**中间那一格——用双目自监督预训练出的、可迁移的几何先验模块——两篇都没碰。** 考虑到 Stereo Transformer 目前是从 100 条示教里从头学极线对应的（这显然是最不合理的一环），而 DROID 这类带双目对的大规模数据已经存在，这一格大概率是这条线上下一个明显的增量。
